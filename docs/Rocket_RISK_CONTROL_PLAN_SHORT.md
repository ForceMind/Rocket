# Rocket Crash 新风控方案

## 1. 这次要新增什么功能

这次不是改一个爆点公式。

而是新增一套完整的动态风控。

要加的功能有 9 个：

1. 今日 RTP 风控。
2. 本周 RTP 风控。
3. 风控模式。
4. 动态平台优势。
5. 动态即爆概率。
6. 普通爆点随机扣点。
7. 单次总赔付上限。
8. 个人 RTP 单人局风控。
9. 放水预算和奖池超额扣除。

已有功能继续保留：

- 奖池上限爆点。
- 机器人不计入真实盈亏。
- 机器人不计入 RTP。

## 2. 每个功能要判断什么，为什么这么设计

### 2.1 今日 RTP 风控

要判断：

- 今日真人下注总额。
- 今日真人返奖总额。
- 今日真人完成局数。
- 今日 RTP 是否过高、过低、正常。

为什么加：

今日 RTP 用来处理短期波动。

如果今天玩家赢太多，平台当天会亏，需要轻微收紧。

如果今天平台赚太多，玩家体验会差，需要轻微放水。

判断规则：

```text
今日RTP = 今日真人返奖 / 今日真人下注
```

建议：

```text
目标RTP = 96%
今日允许上下 20 个百分点
今日正常范围 = 76% 到 116%
```

条件不足时不判断。

建议门槛：

```text
今日真人下注 >= 100000.00
今日真人完成局数 >= 30
```

只要有一个不满足，今日状态就是“样本不足”。

### 2.2 本周 RTP 风控

要判断：

- 本周真人下注总额。
- 本周真人返奖总额。
- 本周真人完成局数。
- 本周 RTP 是否过高、过低、正常。

为什么加：

本周 RTP 用来判断平台整体方向。

今日 RTP 可能波动很大。

本周 RTP 更稳定，所以本周优先级高于今日。

判断规则：

```text
本周RTP = 本周真人返奖 / 本周真人下注
```

建议：

```text
目标RTP = 96%
本周允许上下 5 个百分点
本周正常范围 = 91% 到 101%
```

数据不足时不判断。

建议数据门槛：

```text
本周真人下注 >= 500000.00
本周真人完成局数 >= 1000
```

只要有一个不满足，本周状态就是“样本不足”。

### 2.3 风控模式

要判断：

- 今日 RTP 状态。
- 本周 RTP 状态。

为什么加：

不能只写“收紧”或“放水”。

服务器需要把不同情况变成明确的模式，再由模式输出具体参数。

模式包括：

- 正常。
- 轻收紧。
- 强收紧。
- 极强收紧。
- 轻放水。
- 强放水。

设计原则：

- 本周 RTP 高，优先收紧。
- 本周 RTP 低，优先放水。
- 今日 RTP 只做短期修正。
- 两个周期都样本不足，就正常跑。

### 2.4 动态平台优势

要判断：

- 当前风控模式。

为什么加：

平台优势控制普通随机爆点的整体高低。

平台亏得多，就提高平台优势。

平台赚得多，就降低平台优势。

原理：

```text
平台系数 = 1 - 平台优势
普通爆点 = 平台系数 / (1 - 随机数)
```

平台优势越高，普通爆点整体越低。

平台优势越低，普通爆点整体越高。

### 2.5 动态即爆概率

要判断：

- 当前风控模式。
- 是否命中单人高 RTP 风控。

为什么加：

1.00x 即爆是最直接的风险控制。

平台亏损明显时，可以提高即爆概率。

平台赚多时，可以降低即爆概率。

单人高 RTP 用户自己玩的时候，也可以额外提高即爆概率。

原理：

```text
如果 随机数 < 即爆概率
则 爆点 = 1.00x
```

### 2.6 普通爆点随机扣点

要判断：

- 本局是否没有命中 1.00x 即爆。
- 是否生成了普通随机爆点。

为什么加：

普通随机爆点生成后，再轻微扣掉一点，给平台增加一点边际。

这个扣点很小，玩家体感不明显。

原理：

```text
扣点 = 0.01 到 0.05
扣点后爆点 = 普通随机爆点 - 扣点
```

限制：

- 即爆局不扣。
- 扣完不能低于 1.00x。

### 2.7 单次总赔付上限

要判断：

- 本局真人总下注。
- 后台设置的单次总赔付上限。

为什么加：

奖池够赔，不代表这一局就应该赔很多。

需要单独设置：

```text
这一局最多允许总返奖多少
```

这就是你说的：

```text
正常随机爆点不可以大于 设定值 / 此次总下注额
```

原理：

```text
单次总赔付上限爆点 = 单次总赔付上限 / 本局真人总下注
```

例子：

```text
单次总赔付上限 = 500.00
本局真人总下注 = 100.00
单次总赔付上限爆点 = 5.00x
```

如果随机爆点是 20.00x，最终也不能超过 5.00x。

### 2.8 个人 RTP 单人局风控

要判断：

- 用户累计真人下注。
- 用户累计真人返奖。
- 用户累计真人局数。
- 用户净赢金额。
- 用户个人 RTP。
- 本局真人数量。

为什么加：

有些用户运气太好，生命周期 RTP 过高。

但公共局里不能因为一个高 RTP 用户影响所有人。

所以只在这个用户自然单人玩的时候启用。

触发条件：

```text
累计真人下注 >= 500.00
累计真人局数 >= 50
累计净赢 >= 1000.00
个人RTP >= 120%
本局真人数量 = 1
```

生效后：

```text
即爆概率额外增加 20%
最大爆点限制到 2.50x
```

如果本局有多个真人：

```text
个人 RTP 不参与爆点限制
```

### 2.9 放水预算和奖池超额扣除

要判断：

- 今日 RTP 是否过低。
- 本周 RTP 是否过低。
- 奖池是否超过目标金额。

为什么加：

平台赚多了，不能一直收紧。

需要让 RTP 慢慢回到目标附近。

奖池也不能无限堆高。

超额奖池可以拆成：

- 平台利润。
- 放水预算。

放水做什么：

- 降低平台优势。
- 降低即爆概率。
- 放宽 RTP 最大爆点。

放水不能突破：

- 单次总赔付上限。
- 奖池上限。
- 单人高 RTP 上限。

## 3. 风控模式怎么选

服务器先得到：

```text
今日状态 = 高 / 正常 / 低 / 样本不足
本周状态 = 高 / 正常 / 低 / 样本不足
```

含义：

- 高：RTP 高，玩家返奖多，平台偏亏。
- 低：RTP 低，玩家返奖少，平台赚多。
- 正常：在允许范围内。
- 样本不足：数据不够，不参与强判断。

模式选择：

| 本周状态 | 今日状态 | 本局模式 | 原因            |
| ---- | ---- | ---- | ------------- |
| 高    | 高    | 极强收紧 | 本周和今天都偏亏      |
| 高    | 正常   | 强收紧  | 本周偏亏，优先处理本周   |
| 高    | 低    | 轻收紧  | 本周偏亏，但今天已回落   |
| 高    | 样本不足 | 强收紧  | 今日不足，按本周处理    |
| 正常   | 高    | 轻收紧  | 今天偏亏          |
| 正常   | 正常   | 正常   | 不干预           |
| 正常   | 低    | 轻放水  | 今天平台赚多        |
| 正常   | 样本不足 | 正常   | 本周正常，今日不足     |
| 低    | 高    | 正常   | 本周赚多，但今天已返奖偏高 |
| 低    | 正常   | 轻放水  | 本周平台赚多        |
| 低    | 低    | 强放水  | 本周和今天都赚多      |
| 低    | 样本不足 | 轻放水  | 今日不足，按本周处理    |
| 样本不足 | 高    | 轻收紧  | 本周不足，按今日处理    |
| 样本不足 | 正常   | 正常   | 今日正常          |
| 样本不足 | 低    | 轻放水  | 今日平台赚多        |
| 样本不足 | 样本不足 | 正常   | 数据都不足，正常跑     |

## 4. 每个模式输出什么参数

| 本局模式 | 平台优势 | 即爆概率 | RTP最大爆点 | 放水  |
| ---- | ----:| ----:| -------:| --- |
| 正常   | 1.5% | 1.5% | 后台最大爆点  | 否   |
| 轻收紧  | 2.5% | 2.5% | 20.00x  | 否   |
| 强收紧  | 5%   | 8%   | 5.00x   | 否   |
| 极强收紧 | 8%   | 15%  | 2.50x   | 否   |
| 轻放水  | 1%   | 1%   | 后台最大爆点  | 是   |
| 强放水  | 0.5% | 0.5% | 后台最大爆点  | 是   |

服务器要把这些保存到本局：

```text
roundRiskMode
roundHouseEdgeBps
roundInstantCrashBps
roundRtpMaxCrash
roundWaterEnabled
```

## 5. 一局服务器怎么执行

### 5.1 下注结束后固定输入数据

下注阶段结束后，服务器固定：

```text
roundHumanBetCents
roundHumanPlayerCount
roundBotPlayerCount
roundHumanPlayerIds
prizePoolCents
```

当前这一局还没有结果，所以不计入今日 RTP、本周 RTP。

### 5.2 判断今日和本周状态

服务器先看今日、本周数据是否满足最低样本。

满足后再计算 RTP。

得到：

```text
dayState
weekState
```

### 5.3 选择风控模式

根据模式表得到：

```text
roundRiskMode
```

再根据模式输出：

```text
roundHouseEdgeBps
roundInstantCrashBps
roundRtpMaxCrash
```

### 5.4 判断是否单人高 RTP

如果：

```text
roundHumanPlayerCount = 1
并且唯一真人是高 RTP 用户
```

则启用：

```text
personalSoloRisk = true
```

启用后：

```text
roundInstantCrashBps += 2000
personalSoloMaxCrash = 250
```

否则：

```text
personalSoloRisk = false
personalSoloMaxCrash 不参与最终 min
```

### 5.5 生成随机爆点

先判断即爆。

如果命中即爆：

```text
randomAfterDeductCrash = 100
instantCrash = true
deduct = 0
```

如果没有即爆：

```text
用平台优势生成普通随机爆点
再随机扣 0.01 到 0.05
得到 randomAfterDeductCrash
```

### 5.6 计算单次总赔付上限爆点

如果本局没有真人下注：

```text
roundPayoutCapCrash 不参与最终 min
```

如果有真人下注：

```text
roundPayoutCapCrash = floor(roundMaxTotalPayoutCents * 100 / roundHumanBetCents)
```

建议：

```text
roundMaxTotalPayoutCents = 50000
```

也就是单次总赔付上限 500.00。

### 5.7 计算已有奖池上限爆点

奖池上限已有，继续用。

```text
poolCapCrash = floor(prizePoolCents * 100 / roundHumanOpenBetCents)
```

飞行中可以继续根据剩余未取现真人更新。

### 5.8 得到最终爆点

服务器取所有适用限制里的最小值。

```text
finalCrash = min(
  randomAfterDeductCrash,
  adminMaxCrash,
  roundRtpMaxCrash,
  roundPayoutCapCrash,
  poolCapCrash,
  personalSoloMaxCrash
)
```

不适用的限制不放进去。

### 5.9 记录限制原因

如果最终爆点等于哪个限制，就记录哪个原因。

限制原因：

```text
random
admin_max
rtp_risk
round_payout_cap
pool_cap
personal_solo_rtp
```

如果多个限制值一样，建议优先级：

```text
personal_solo_rtp
round_payout_cap
pool_cap
rtp_risk
admin_max
random
```

## 6. 已有奖池上限和新增单次上限的区别

奖池上限：

```text
防止奖池赔不起
```

单次总赔付上限：

```text
防止一局赔太多
```

两者都要用。

最终哪个更低，就哪个生效。

例子：

```text
随机扣点后爆点 = 20.00x
奖池上限爆点 = 8.00x
单次总赔付上限爆点 = 5.00x
```

最终：

```text
finalCrash = 5.00x
限制原因 = round_payout_cap
```

## 9. 实现顺序

第一步：

- 今日 RTP、本周 RTP 统计。
- 样本是否足够判断。
- 风控模式选择。
- 总览报表。

第二步：

- 风控模式输出平台优势、即爆概率、RTP 最大爆点。
- 普通爆点扣点。

第三步：

- 单次总赔付上限爆点。
- 最终爆点取 min。
- 限制原因。
- 回合报表。

第四步：

- 个人 RTP。
- 自然单人高 RTP 风控。

第五步：

- 放水预算。
- 奖池超额扣除。
- 风控日志。
