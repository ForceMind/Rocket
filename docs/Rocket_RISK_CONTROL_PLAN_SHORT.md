# Rocket Crash 动态风控方案 PRD

## 1. 概述

本方案为 Rocket Crash 增加一套动态风控系统。

系统通过今日 RTP、本周 RTP、个人 RTP、单局总下注、奖池余额等数据，动态决定每局的风控模式，并最终影响爆点。

保留现有功能：

- 奖池上限爆点。
- 机器人隔离统计。
- 机器人不计入真实盈亏和 RTP。

新增功能：

- 今日 RTP 短期风控。
- 本周 RTP 主趋势风控。
- 动态平台优势。
- 动态即爆概率。
- 普通随机爆点扣除 0.01x 到 0.05x。
- 单次总赔付上限。
- 个人高 RTP 单人局风控。
- 放水预算。
- 奖池超额扣除。
- 风控报表和限制原因记录。

## 2. 核心机制

### 2.1 周期 RTP 监控

系统按两个周期监控 RTP。

本周 RTP 是主判断。

今日 RTP 是短期修正。

#### 本周 RTP

用途：

- 判断平台整体收益方向。
- 优先级高于今日 RTP。

判断数据：

- 本周真人下注总额。
- 本周真人返奖总额。
- 本周真人完成局数。

建议生效门槛：

```text
本周真人下注 >= 5000.00
本周真人完成局数 >= 100
```

判断范围：

```text
目标 RTP = 96%
正常范围 = 91% 到 101%
```

含义：

- 本周 RTP 高于 101%：平台本周偏亏，需要收紧。
- 本周 RTP 低于 91%：平台本周赚多，可以放水。
- 数据没达到门槛：本周状态为样本不足。

#### 今日 RTP

用途：

- 修正单日波动。
- 本周状态正常或不足时，才更明显影响决策。

判断数据：

- 今日真人下注总额。
- 今日真人返奖总额。
- 今日真人完成局数。

建议生效门槛：

```text
今日真人下注 >= 1000.00
今日真人完成局数 >= 30
```

判断范围：

```text
目标 RTP = 96%
正常范围 = 76% 到 116%
```

含义：

- 今日 RTP 高于 116%：平台今天偏亏，轻收紧。
- 今日 RTP 低于 76%：平台今天赚多，轻放水。
- 数据没达到门槛：今日状态为样本不足。

### 2.2 动态风控参数

系统根据风控模式动态输出三类参数。

#### 平台优势

作用：

- 控制普通随机爆点整体高低。

原理：

```text
平台系数 = 1 - 平台优势
普通爆点 = 平台系数 / (1 - 随机数)
```

平台优势越高，普通爆点越低。

平台优势越低，普通爆点越高。

#### 即爆概率

作用：

- 控制 1.00x 直接爆炸的概率。

原理：

```text
如果 随机数 < 即爆概率
则 爆点 = 1.00x
```

#### 普通爆点扣点

作用：

- 普通随机爆点生成后，隐性扣除 0.01x 到 0.05x。
- 增加平台边际收益。

规则：

```text
扣点 = 0.01x 到 0.05x
扣点后爆点 = 普通随机爆点 - 扣点
```

限制：

- 即爆局不扣。
- 扣后不能低于 1.00x。

### 2.3 单局风险限制

#### 单次总赔付上限

用途：

- 限制一局最多允许赔付多少钱。
- 这是新增重点。

区别：

- 奖池上限是防止奖池赔不起。
- 单次总赔付上限是防止单局赔太多。

公式：

```text
单次总赔付上限爆点 = 单次总赔付上限 / 本局真人总下注
```

倍率按整数保存时：

```text
单次总赔付上限爆点 = floor(单次总赔付上限 * 100 / 本局真人总下注)
```

建议：

```text
单次总赔付上限 = 500.00
```

例子：

```text
本局真人总下注 = 100.00
单次总赔付上限 = 500.00
单次总赔付上限爆点 = 5.00x
```

如果随机爆点是 20.00x，最终也不能超过 5.00x。

#### 奖池上限爆点

用途：

- 现有功能继续保留。
- 防止奖池赔穿。

公式：

```text
奖池上限爆点 = 当前奖池余额 / 真人未取现下注
```

飞行中可以根据剩余未取现真人继续更新。

### 2.4 个人高 RTP 单人局风控

用途：

- 限制生命周期 RTP 过高的用户，在自然单人局里继续高额获利。

触发条件：

```text
本局只有 1 名真人
用户累计真人下注 >= 500.00
用户累计真人局数 >= 50
用户净赢 >= 1000.00
用户个人 RTP >= 120%
```

生效规则：

```text
本局即爆概率额外 +20%
本局最大爆点 = 2.50x
```

限制：

- 如果本局有其他真人参与，不生效。
- 个人 RTP 不能影响公共局爆点。

### 2.5 放水和奖池超额扣除

#### 放水

触发：

- 今日 RTP 低于下限。
- 或本周 RTP 低于下限。
- 且有放水预算。

表现：

- 降低平台优势。
- 降低即爆概率。
- 放开 RTP 模式爆点限制。

限制：

- 不能突破单次总赔付上限。
- 不能突破奖池上限。
- 不能突破个人高 RTP 单人局限制。

#### 奖池超额扣除

触发：

```text
当前奖池余额 > 奖池目标金额
```

建议：

```text
奖池目标 = 10000.00
扣除超额部分 20%
70% 进入平台利润
30% 进入放水预算
```

限制：

- 只能回合结束后扣。
- 不能飞行中扣。
- 只能扣超额部分。
- 扣后不能低于奖池目标。

## 3. 风控决策逻辑

### 3.1 状态定义

RTP 状态：

- 高：玩家返奖偏高，平台偏亏。
- 低：玩家返奖偏低，平台赚多。
- 正常：在允许区间内。
- 样本不足：下注额或局数未达到门槛。

### 3.2 决策矩阵

本周状态优先级高于今日状态。

| 本周状态 | 今日状态 | 风控模式 | 说明 |
| --- | --- | --- | --- |
| 高 | 高 | 极强收紧 | 本周和今天都偏亏 |
| 高 | 正常/不足 | 强收紧 | 本周偏亏，优先止损 |
| 高 | 低 | 轻收紧 | 本周偏亏，但今天已有回落 |
| 正常/不足 | 高 | 轻收紧 | 只有今天偏亏 |
| 正常/不足 | 正常/不足 | 正常 | 正常运行 |
| 正常/不足 | 低 | 轻放水 | 今天平台赚多 |
| 低 | 高 | 正常 | 本周赚多，但今天已返奖偏高 |
| 低 | 正常/不足 | 轻放水 | 本周平台赚多 |
| 低 | 低 | 强放水 | 本周和今天都赚多 |

### 3.3 模式参数

| 风控模式 | 平台优势 | 即爆概率 | RTP最大爆点 | 是否消耗放水预算 |
| --- | ---: | ---: | ---: | --- |
| 正常 | 1.5% | 1.5% | 无额外限制 | 否 |
| 轻收紧 | 2.5% | 2.5% | 20.00x | 否 |
| 强收紧 | 5.0% | 8.0% | 5.00x | 否 |
| 极强收紧 | 8.0% | 15.0% | 2.50x | 否 |
| 轻放水 | 1.0% | 1.0% | 无额外限制 | 是 |
| 强放水 | 0.5% | 0.5% | 无额外限制 | 是 |

## 4. 单局最终爆点

每局最终爆点由所有适用限制取最小值得出。

```text
最终爆点 = min(
  随机扣点后爆点,
  后台最大爆点,
  RTP模式最大爆点,
  单次总赔付上限爆点,
  奖池上限爆点,
  个人高RTP单人局最大爆点
)
```

不适用的限制不参与计算。

例如：

- 没有真人下注时，单次总赔付上限不参与。
- 不是单人高 RTP 局时，个人高 RTP 最大爆点不参与。

### 限制原因

每局要记录最终爆点被哪个限制项决定。

原因枚举：

```text
random
admin_max
rtp_risk
round_payout_cap
pool_cap
personal_solo_rtp
```

如果多个限制值相同，优先记录：

```text
personal_solo_rtp
round_payout_cap
pool_cap
rtp_risk
admin_max
random
```
