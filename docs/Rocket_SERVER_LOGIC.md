## 1. 游戏服务器的核心原则

Rocket Crash 是一个实时倍率下注游戏。

玩家先下注，火箭起飞后倍率不断上涨。玩家在火箭爆炸前取现就赢，没取现就输。

服务器必须记住四条原则。

第一，服务器是裁判。

前端只能显示，不能决定输赢。

第二，前端不传倍率，也不依据前端表现用于结算。

玩家点击 Cash Out 时，前端可以告诉服务器“我要取现”，但不是告诉服务器“我在 2.35x 取现”。真正的取现倍率必须由服务器在收到请求时的时间自己计算。

第三，自动取现必须由服务器执行。

如果玩家设置 2.00x 自动取现，服务器要在飞到 2.00x 时自动结算，不是让前端自己定时请求。

第四，奖池通过爆点控制风险。

如果奖池不够赔更高倍率，服务器不是拒绝玩家合法下注，也不阻止玩家合法取现，而是应该把本局有效爆点压低到奖池能承受的位置。

用一句话总结：

```text
前端负责看起来像游戏，服务器负责这局游戏到底发生了什么。
```

## 2. 服务器需要有哪些模块

一套完整 Rocket Crash 服务器至少需要这些模块。

### 配置模块

负责保存后台参数，例如下注档位、最大下注、爆点概率、曲线参数、机器人数量、奖池余额。

### 玩家模块

负责创建玩家、保存余额、保存默认自动取现倍率、保存新手引导完成状态。

### 回合模块

负责一局一局地跑游戏，包括等待下注、起飞、飞行、爆炸、下一局。

### 爆点模块

负责生成随机基础爆点，并处理 1.00x 即爆概率和平台抽水。

### 奖池模块

负责计算当前真人未取现下注总额，并算出奖池能承受的最高倍率。

### 下注模块

负责检查下注是否合法，扣余额，记录下注，把真人下注加入奖池。

### 取现模块

负责手动取现、自动取现、派彩、更新玩家余额和奖池。

### 机器人模块

负责生成机器人、让机器人陆续下注、让机器人按倍率跳出，但机器人不能影响真实盈亏。

### 推送模块

负责把新局、下注、起飞、取现、爆炸、玩家余额变化推给前端。

### 后台模块

负责查看数据、修改配置、设置奖池、强制爆炸、暂停、调整玩家余额、清理统计。

### 数据模块

负责保存玩家、回合历史、配置、审计日志，并且处理数据损坏或保存失败。

## 3. 服务器启动时要做什么

服务器启动时不能直接开始乱跑。它要按顺序做初始化。

启动流程如下。

```text
1. 读取环境变量。
2. 决定监听端口。
3. 决定是否启用 HTTPS。
4. 读取或创建数据文件。
5. 合并默认配置和已保存配置。
6. 修正非法配置。
7. 初始化内存里的当前回合。
8. 如果没有暂停，也没有维护，就创建第一局。
9. 启动定时循环。
10. 开始监听 HTTP 和 WebSocket。
```

如果要支持 HTTPS，服务器必须同时拿到证书和私钥。只给证书或只给私钥都应该报错。

如果出现错误，不要直接崩溃。生产版应该进入维护，等待人工处理。



```text
如果数据出错：
    进入维护
    停止开新局
    通知管理员
```

## 5. 金额为什么必须用整数

钱不能用小数保存。

原因是很多编程语言的小数会有精度误差。

例如 0.1 加 0.2，在一些语言里不一定精确等于 0.3。

所以服务器里统一用最小单位保存钱。

如果货币单位是元，就用分保存。

中文说明：10 元在服务器里保存成 1000 分。

公式如下。

```text
金额分 = 金额元 × 100
金额元 = 金额分 ÷ 100
```

下注、派彩、奖池、玩家余额都用“分”。

例如：

```text
玩家余额 900.00 元 -> 90000 分
下注 10.00 元 -> 1000 分
奖池 100000.00 元 -> 10000000 分
```

服务器展示给前端时，再把分转成元。

## 7. 回合状态机

Rocket 游戏是一局一局循环的。

每局有三个核心阶段。

### betting

等待下注阶段。

玩家可以下注，不能取现。

机器人会在这个阶段陆续下注。

### flying

火箭飞行阶段。

玩家不能再下注。

玩家可以手动取现。

服务器会处理自动取现。

服务器会判断是否爆炸。

### crashed

火箭已经爆炸。

玩家不能下注，也不能取现。

服务器停留 3 秒，让前端显示爆炸结果，然后开下一局。

状态流转如下。

```text
没有当前回合
    -> 创建新回合
    -> betting
    -> 倒计时结束
    -> flying
    -> 达到有效爆点
    -> crashed
    -> 停留 3 秒
    -> 清空当前回合
    -> 创建新回合
```

如果后台暂停：

```text
没有当前回合时，不创建新回合。
已经进行中的回合，可以继续跑完，也可以按产品规则处理。
```

## 8. 定时循环怎么跑

服务器需要一个循环定时器。

它不负责画面帧率，而是负责推进游戏状态。

开发版可以每 50 毫秒跑一次。

伪代码如下。

这段伪代码的意思是：服务器每隔很短时间检查当前回合处于什么阶段，然后做该阶段应该做的事。

```text
每 50 毫秒执行 tick：
    当前时间 = 服务器当前时间

    如果没有当前回合：
        如果没有暂停也没有维护：
            创建新回合
        结束本次 tick

    如果当前阶段是 betting：
        执行到时间的机器人下注
        如果当前时间 >= 下注结束时间：
            开始飞行

    如果当前阶段是 flying：
        计算当前倍率
        处理自动取现
        更新奖池有效爆点
        如果当前倍率 >= 有效爆点：
            爆炸结算

    如果当前阶段是 crashed：
        如果当前时间 >= 下一局开始时间：
            清空当前回合
            创建新回合
```

注意：不要依赖前端消息来推进回合。

即使没有任何玩家在线，服务器也应该自己能开局、起飞、爆炸、下一局。

## 9. 创建新回合

创建新回合时，服务器要准备本局所有基础数据。

流程如下。

```text
1. 如果后台暂停，不创建。
2. 如果已经有当前回合，不创建。
3. 生成 serverSeed。
4. 读取并递增 nonce。
5. 用 serverSeed 和 nonce 计算本局随机基础爆点。
6. 记录创建时间。
7. 计算下注结束时间。
8. 初始化当前倍率为 1.00。
9. 初始化下注列表为空。
10. 初始化机器人下注计划。
11. 保存数据。
12. 推送新回合开始消息。
```

serverSeed 是服务器内部随机种子。

nonce 是递增局号，用来让每局随机结果不同。

玩家端不需要看到 serverSeed，也不需要看到 seedHash。后台可以保留用于调试和复算。

创建回合伪代码如下。

这段伪代码的意思是：只有在没有当前回合且没有暂停时，服务器才会创建新局。

```text
如果 paused 是 true：
    不创建回合

如果 currentRound 已存在：
    不创建回合

serverSeed = 生成 32 字节随机数
nonce = 当前 nonce
nonce 自增 1
基础爆点 = 根据 serverSeed 和 nonce 计算
createdAt = 当前服务器时间

currentRound = {
    id: 新回合 ID,
    phase: betting,
    serverSeed: serverSeed,
    seedHash: serverSeed 的 SHA256,
    nonce: nonce,
    randomCrashMultiplier: 基础爆点,
    crashMultiplier: 基础爆点,
    currentMultiplier: 1.00,
    createdAt: createdAt,
    bettingEndsAt: createdAt + 等待下注时间,
    bets: 空数组,
    botPlan: 机器人下注计划
}
```

## 10. 爆点生成逻辑

爆点是火箭在哪个倍率爆炸。

服务器生成爆点分三层。

第一层：判断是否 1.00x 即爆。

第二层：如果不是即爆，计算随机基础爆点。

第三层：用奖池承受能力压低成最终有效爆点。

中文解释：

```text
随机基础爆点决定这局原本想飞到哪里。
奖池有效爆点决定这局最多能飞到哪里。
真正爆炸用的是最终有效爆点。
```

最终规则如下。

```text
最终有效爆点 = 随机基础爆点 和 奖池上限倍率 中较小的那个
```

如果没有真人下注，奖池不需要压低爆点。

## 11. 1.00x 即爆逻辑

1.00x 即爆就是火箭刚开始就爆。

后台配置：

```text
instantCrashBps
```

中文解释：这个值表示每局直接 1.00x 爆炸的概率，单位是 bps。

先把 bps 转成概率。

```text
即爆概率 = instantCrashBps ÷ 10000
```

例如：

```text
instantCrashBps = 150
即爆概率 = 150 ÷ 10000 = 0.015 = 1.5%
```

服务器每局生成一个 0 到 1 之间的随机数。

如果随机数小于即爆概率，本局爆点就是 1.00x。

伪代码如下。

这段伪代码的意思是：先抽随机数，如果命中即爆区间，直接返回 1.00。

```text
random = 0 到 1 之间的随机数
instantChance = instantCrashBps ÷ 10000

如果 random < instantChance：
    本局基础爆点 = 1.00
```

## 12. 随机基础爆点公式

如果没有命中 1.00x 即爆，就继续计算基础爆点。

当前推荐用 HMAC 生成随机数。

中文解释：HMAC 可以让同一个 serverSeed 和 nonce 算出固定结果，方便后台复算，也能避免普通随机数不容易追踪的问题。

步骤如下。

```text
1. 用 serverSeed 做 HMAC 密钥。
2. 用 nonce 做 HMAC 内容。
3. 得到一个 sha256 十六进制字符串。
4. 取前 13 个十六进制字符。
5. 把它转成整数。
6. 除以 16 的 13 次方，得到 0 到 1 之间的随机数。
```

变量说明：

```text
H = HMAC_SHA256(serverSeed, nonce)
S = H 的前 13 个十六进制字符转成整数
D = 16 的 13 次方
R = S ÷ D
```

公式如下。

```text
R = S ÷ D
```

R 就是本局随机数，范围大约是 0 到 1。

为什么取前 13 个十六进制字符：

```text
13 个十六进制字符有足够随机空间，也能安全转成常用语言里的数字。
```

如果前面已经设置了 1.00x 即爆概率，且本局没有命中即爆，要把剩余随机区间重新映射到 0 到 1。

中文解释：因为 random 的一小段已经拿来做即爆了，普通爆点只应该使用剩下的随机区间。

变量说明：

```text
R = 原始随机数
P = 即爆概率
A = 调整后的随机数
```

公式如下。

```text
A = (R - P) ÷ (1 - P)
```

如果 P 是 0，就等于没有即爆区间。

平台抽水用 houseEdgeBps 表示。

中文解释：平台抽水越高，长期平均爆点越低。

变量说明：

```text
E = houseEdgeBps
F = 平台系数
```

公式如下。

```text
F = 1 - E ÷ 10000
```

例如：

```text
houseEdgeBps = 150
F = 1 - 150 ÷ 10000 = 0.985
```

基础爆点公式如下。

中文解释：调整后的随机数 A 越接近 1，分母越小，爆点越高；A 越接近 0，爆点越低。

变量说明：

```text
C = 随机基础爆点
F = 平台系数
A = 调整后的随机数
```

公式如下。

```text
C = F ÷ (1 - A)
```

最后要做倍率限制。

中文解释：爆点不能低于 1.01，也不能超过后台最大普通爆点，并且要向下保留两位小数。

公式如下。

```text
C = 向下取两位小数(C)
C = 最大值(C, 1.01)
C = 最小值(C, maxCrashMultiplier)
```

完整伪代码如下。

这段伪代码的意思是：先用 HMAC 得到随机数，再处理即爆，再按抽水公式算基础爆点。

```text
H = HMAC_SHA256(serverSeed, nonce)
S = H 前 13 位十六进制转整数
D = 16 的 13 次方
R = S ÷ D
R = 限制在大于 0 且小于 1

P = instantCrashBps ÷ 10000

如果 R < P：
    返回 1.00

A = (R - P) ÷ (1 - P)
F = 1 - houseEdgeBps ÷ 10000
C = F ÷ (1 - A)
C = 向下取两位小数(C)
C = 限制在 1.01 到 maxCrashMultiplier 之间
返回 C
```

## 13. 奖池风险控制

奖池是用来赔真人玩家的钱。

真人下注会增加奖池。

真人取现会减少奖池。

机器人不影响奖池。

奖池的核心作用：限制有效爆点。

中文解释：如果当前所有还没取现的真人玩家一起在某个倍率取现，奖池必须赔得起。如果奖池赔不起，就让火箭在那之前爆炸。

先计算真人未取现下注总额。

变量说明：

```text
O = 真人未取现下注总额
```

公式如下。

```text
O = 所有真人 open 下注金额之和
```

再计算奖池上限倍率。

变量说明：

```text
P = 当前奖池余额
O = 真人未取现下注总额
L = 奖池上限倍率
```

公式如下。

```text
L = P ÷ O
```

如果 O 等于 0，说明没有真人未取现下注，奖池上限可以认为是后台最大爆点。

奖池上限要向下保留两位小数。

```text
L = 向下取两位小数(P ÷ O)
```

例子：

```text
奖池余额 P = 10000
真人未取现下注总额 O = 2000
奖池上限 L = 10000 ÷ 2000 = 5.00
```

意思是：如果所有真人都在 5.00x 取现，奖池刚好赔完。

最终有效爆点如下。

变量说明：

```text
C = 随机基础爆点
L = 奖池上限倍率
E = 最终有效爆点
```

公式如下。

```text
E = C 和 L 中较小的那个
```

也就是：

```text
E = min(C, L)
```

注意：

```text
奖池不足时，不拒绝合法下注。
奖池不足时，不阻止合法取现。
奖池不足时，只压低有效爆点。
```

## 14. 有效爆点怎么更新

有效爆点不是只在开局算一次。

它要在多个时机重新计算。

必须更新的时机：

```text
1. 真人下注成功后。
2. 真人手动取现前。
3. 真人手动取现后。
4. 自动取现处理前。
5. 自动取现处理后。
6. 每次飞行 tick 中。
7. 后台手动调整奖池后。
8. 后台强制爆炸前。
```

为什么要频繁更新：

```text
下注会增加真人未取现总额和奖池。
取现会减少奖池，也会减少真人未取现总额。
这两个值变化后，奖池上限就可能变化。
```

更新伪代码如下。

这段伪代码的意思是：每次都重新计算当前真人 open 金额和奖池上限，然后把本局爆点改成基础爆点和奖池上限中更小的值。

```text
如果没有当前回合：
    不处理

如果当前回合已经 crashed：
    不处理

baseCrash = currentRound.randomCrashMultiplier
openHumanBet = 真人 open 下注总额

如果 openHumanBet <= 0：
    poolCap = baseCrash
否则：
    poolCap = 向下取两位小数(奖池余额 ÷ openHumanBet)

effectiveCrash = min(baseCrash, poolCap)

currentRound.poolCapMultiplier = poolCap
currentRound.crashMultiplier = effectiveCrash
currentRound.poolCapped = openHumanBet > 0 且 poolCap < baseCrash
```

## 15. 倍率增长曲线

倍率由服务器时间决定。

先算已飞行时间。

变量说明：

```text
T = 已飞行毫秒数
now = 当前服务器时间
launchAt = 起飞时间
```

公式如下。

```text
T = now - launchAt
```

然后把 T 放进倍率公式。

当前推荐使用两段曲线：

```text
1.00x 到 20.00x：前段曲线
20.00x 以后：后段曲线
```

## 16. 为什么曲线分前段和后段

20x 以前是玩家最常操作的区间。

大多数玩家会在 1.20x、1.50x、2.00x、3.00x 这些倍率纠结，所以前段要更容易调节。

20x 以后是高倍率区间。

如果继续用前段曲线，后期可能显得太慢；如果全部用普通指数，前期又可能太快。

所以分段：

```text
前段负责游戏手感。
后段负责高倍率继续加速。
```

## 17. 当前倍率怎么计算

前段目标倍率固定为 20。

后台配置：

```text
earlyTargetMs = 从 1.00x 到 20.00x 的目标时间
earlyPower = 前段曲线指数
lateSpeedMs = 20.00x 后的速度时间
```

前段先算进度。

变量说明：

```text
T = 已飞行毫秒数
D = earlyTargetMs
P = 前段进度
```

公式如下。

```text
P = T ÷ D
```

P 要限制在 0 到 1。

再算弯曲后的进度。

中文解释：0.02 的线性部分是为了避免开头长期停在 1.00x；0.98 的指数部分决定主要加速曲线。

变量说明：

```text
P = 前段进度
W = 线性权重，默认 0.02
K = 前段曲线指数，默认 2.4
EP = 弯曲后的进度
```

公式如下。

```text
EP = W × P + (1 - W) × P 的 K 次方
```

默认值写出来就是：

```text
EP = 0.02 × P + 0.98 × P 的 2.4 次方
```

再算前段倍率。

变量说明：

```text
M = 当前倍率
EP = 弯曲后的进度
```

公式如下。

```text
M = 1 + 19 × EP
```

为什么是 19：

```text
20.00 - 1.00 = 19.00
```

后段倍率这样算。

中文解释：超过 20x 后，使用指数增长。lateSpeedMs 越小，后段涨得越快；lateSpeedMs 越大，后段涨得越慢。

变量说明：

```text
T = 已飞行毫秒数
D = earlyTargetMs
S = lateSpeedMs
M = 当前倍率
e = 自然常数，约等于 2.71828
```

公式如下。

```text
M = 20 × e 的 ((T - D) ÷ S) 次方
```

完整伪代码如下。

这段伪代码的意思是：如果还没到 20x 的目标时间，就用前段公式；超过目标时间后，用后段指数公式。

```text
function multiplierFromElapsed(T):
    T = max(0, T)

    如果 T <= earlyTargetMs：
        P = T ÷ earlyTargetMs
        EP = 0.02 × P + 0.98 × P 的 earlyPower 次方
        M = 1 + 19 × EP
    否则：
        M = 20 × e 的 ((T - earlyTargetMs) ÷ lateSpeedMs) 次方

    如果 M 不是有效数字：
        M = 一个很大的安全值

    返回 M
```

服务器用于结算和爆炸判断时，要向下保留两位小数。

中文解释：不要四舍五入，因为四舍五入可能把玩家还没达到的倍率抬高。

公式如下。

```text
两位倍率 = 向下取整(原始倍率 × 100) ÷ 100
```

例子：

```text
2.349 -> 2.34
2.999 -> 2.99
```

## 18. 等待下注阶段

等待下注阶段叫 betting。

这个阶段服务器允许玩家下注，不允许玩家取现。

服务器要做：

```text
1. 等待玩家下注。
2. 执行到时间的机器人下注。
3. 每次下注后更新奖池有效爆点。
4. 倒计时结束后进入 flying。
```

下注倒计时由服务器时间控制。

变量说明：

```text
createdAt = 回合创建时间
bettingDurationMs = 等待下注时间
bettingEndsAt = 下注结束时间
```

公式如下。

```text
bettingEndsAt = createdAt + bettingDurationMs
```

如果当前服务器时间达到 bettingEndsAt，服务器必须起飞。

```text
如果 now >= bettingEndsAt：
    startFlying()
```

## 19. 真人下注逻辑

玩家下注时，服务器必须逐项校验。

不能只看前端按钮是否可点。

下注校验顺序建议如下。

```text
1. 玩家存在。
2. 当前有回合。
3. 当前阶段是 betting。
4. 当前时间还没超过下注结束时间。
5. 下注金额能转成整数分。
6. 下注金额 >= 最小下注。
7. 下注金额 <= 最大下注。
8. 下注金额必须等于某个筹码档位。
9. 玩家余额足够。
10. 玩家本局还没下注过。
11. 自动取现倍率为空，或者在 1.01 到最大爆点之间。
```

校验通过后，服务器才执行扣款和记录。

流程如下。

```text
1. 如果玩家设置了自动取现，保存到玩家默认自动取现倍率。
2. 玩家余额减少下注金额。
3. 奖池增加下注金额。
4. 创建 bet。
5. bet 状态设为 open。
6. 把 bet 加入当前回合。
7. 更新有效爆点。
8. 写审计日志。
9. 保存数据。
10. 推送 bet_placed。
11. 单独推送玩家余额更新。
```

注意：

```text
奖池不足不能拒绝合法下注。
下注成功后，如果奖池承受不了高倍率，有效爆点会被压低。
```

下注伪代码如下。

这段伪代码的意思是：只有所有校验都通过，才扣余额、加奖池、创建下注。

```text
function placeBet(playerId, amount, autoCashout):
    player = 查找玩家
    amountCents = 金额转分(amount)

    如果 currentRound 不存在或 phase 不是 betting：
        报错：下注已关闭

    如果 amountCents 不在允许筹码档位：
        报错：下注金额必须是筹码档位

    如果 amountCents > player.balanceCents：
        报错：余额不足

    如果 currentRound 已有这个玩家的下注：
        报错：本局已下注

    如果 autoCashout 不为空且不合法：
        报错：自动取现倍率无效

    如果 autoCashout 不为空：
        player.defaultAutoCashout = autoCashout

    player.balanceCents -= amountCents
    settings.prizePoolCents += amountCents

    bet = 创建 open 下注
    currentRound.bets.push(bet)

    updateEffectiveCrashMultiplier("human-bet")
    保存数据
    推送下注
    推送玩家余额
```

## 20. 机器人下注逻辑

机器人只用于氛围，不参与真实盈亏。

机器人必须陆续下注，不能起飞前一秒全部出现。

创建回合时，服务器先生成机器人计划。

计划包括：

```text
机器人名字
下注时间
下注金额
自动取现倍率
是否已下注
```

机器人数量从后台配置的最小值和最大值之间随机。

中文解释：每局机器人数量不是固定的，避免看起来太假。

公式如下。

```text
机器人数量 = botMinCount 到 botMaxCount 之间的随机整数
```

机器人第一笔下注不要立刻出现，可以延迟 350 毫秒。

最后一笔机器人下注要尽量早于起飞，例如起飞前 1100 毫秒。

机器人下注间隔从后台最小间隔和最大间隔之间随机。

```text
下一次机器人下注时间 = 上一次下注时间 + 随机间隔
```

如果等待下注时间太短，服务器要限制实际能安排的机器人数量，避免所有机器人挤在最后。

机器人下注金额必须来自筹码档位。

中文解释：玩家看到机器人下注也应该是 10、50、100、500 这种整数筹码，而不是 37.23。

机器人自动取现倍率建议分布如下。

```text
58% 的机器人：1.15x 到 2.50x
30% 的机器人：2.50x 到 6.00x
12% 的机器人：6.00x 到 20.00x
```

伪代码如下。

这段伪代码的意思是：根据随机数决定机器人属于低倍率、中倍率还是高倍率跳出。

```text
roll = 0 到 1 的随机数

如果 roll < 0.58：
    autoCashout = 1.15 到 2.50 之间随机
否则如果 roll < 0.88：
    autoCashout = 2.50 到 6.00 之间随机
否则：
    autoCashout = 6.00 到 20.00 之间随机
```

每次 tick 在 betting 阶段检查哪些机器人到下注时间。

机器人下注时：

```text
1. 标记机器人计划 placed = true。
2. 创建一笔 isBot = true 的 open 下注。
3. 不扣任何真实余额。
4. 不增加奖池。
5. 推送 bet_placed。
6. 保存数据。
```

## 21. 起飞逻辑

当服务器时间达到 bettingEndsAt，回合进入 flying。

起飞前要先判断纯机器人高飞逻辑，后面会单独讲。

起飞时服务器要做：

```text
1. 如果当前阶段不是 betting，不处理。
2. 检查是否触发纯机器人高飞。
3. phase 改成 flying。
4. launchAt = 当前服务器时间。
5. currentMultiplier = 1.00。
6. 固定本局曲线参数快照。
7. 推送 flight_start。
```

注意：

```text
前端可以显示 Starting Soon。
但服务器从 launchAt 开始就已经真实飞行。
```

起飞伪代码如下。

这段伪代码的意思是：下注结束后，服务器记录准确起飞时间，并把本局曲线参数固定下来。

```text
function startFlying():
    如果 currentRound 不存在或 phase 不是 betting：
        返回

    applyBotOnlyHighFlight()

    currentRound.phase = flying
    currentRound.launchAt = 当前服务器时间
    currentRound.currentMultiplier = 1.00
    currentRound.curve = 当前曲线配置快照

    推送 flight_start
```

## 22. 飞行中服务器要做什么

飞行中是服务器最关键的阶段。

每次 tick 要按顺序做：

```text
1. 用服务器时间计算当前倍率。
2. 写入 currentRound.currentMultiplier。
3. 处理自动取现。
4. 更新有效爆点。
5. 判断是否达到有效爆点。
6. 如果达到，爆炸结算。
7. 如果没达到，但状态变化了，保存数据。
```

为什么先处理自动取现，再判断爆炸：

```text
如果玩家设置自动取现 2.00x，本局有效爆点 2.10x，
当服务器算到 2.00x 时，玩家应该先成功取现。
```

但如果本局有效爆点是 1.80x：

```text
服务器在 1.80x 就爆炸，玩家的 2.00x 自动取现不会成功。
```

飞行 tick 伪代码如下。

这段伪代码的意思是：每次飞行循环都重新算倍率、处理自动取现、检查爆炸。

```text
if currentRound.phase == flying:
    currentMultiplier = multiplierAt(当前服务器时间)
    currentRound.currentMultiplier = currentMultiplier

    autoChanged = processAutoCashouts(currentMultiplier)
    capChanged = updateEffectiveCrashMultiplier("tick")

    if currentMultiplier >= currentRound.crashMultiplier:
        finishRound()
    else if autoChanged 或 capChanged:
        保存数据
```

## 23. 自动取现逻辑

自动取现必须由服务器执行。

玩家下注时如果设置了自动取现倍率，服务器把这个倍率保存到 bet 里。

飞行中服务器检查每一笔 open 下注。

自动取现成功需要同时满足：

```text
1. bet.status 是 open。
2. bet.autoCashout 有值。
3. bet.autoCashout 小于当前有效爆点。
4. 当前服务器倍率 >= bet.autoCashout。
```

为什么要求 autoCashout 小于有效爆点：

```text
如果自动取现倍率等于或大于爆点，火箭到那个位置时已经爆炸，不能取现。
```

处理顺序建议按自动取现倍率从低到高。

中文解释：如果多人自动取现，低倍率先跳出。每次跳出都会改变奖池和 open 真人金额，所以每跳出一个人都要重新计算有效爆点。

自动取现伪代码如下。

这段伪代码的意思是：循环寻找当前已经到达自动取现条件的最低倍率下注，结算一个后重新计算奖池，再继续找下一个。

```text
function processAutoCashouts(currentMultiplier):
    changed = false

    循环：
        updateEffectiveCrashMultiplier("auto-cashout")

        bet = 所有满足条件的 open 自动取现下注中，autoCashout 最小的那一笔

        如果没有 bet：
            跳出循环

        settled = cashoutBet(bet, bet.autoCashout, "auto")

        如果 settled 失败：
            跳出循环

        推送 cashout
        updateEffectiveCrashMultiplier("auto-cashout")
        changed = true

    返回 changed
```

自动取现派彩倍率应该用玩家设置的目标倍率。

例子：

```text
玩家设置 Auto Cashout = 2.00x
服务器 tick 时当前倍率已经是 2.03x
只要还没爆炸，玩家按 2.00x 派彩
```

原因：

```text
玩家预约的是 2.00x，不应该因为服务器 tick 间隔多拿到 2.03x。
也不应该因为前端延迟或浏览器后台导致错过。
```

## 24. 手动取现逻辑

手动取现是玩家点击 Cash Out 后，服务器收到请求再处理。

服务器不信任前端传来的倍率。

处理顺序如下。

```text
1. 找到玩家。
2. 检查当前回合是否 flying。
3. 找到玩家本局 open 下注。
4. 更新有效爆点。
5. 用服务器当前时间计算当前倍率。
6. 再更新一次有效爆点。
7. 如果当前倍率 >= 有效爆点，爆炸，取现失败。
8. 如果当前倍率 < 有效爆点，按当前服务器倍率取现成功。
9. 更新有效爆点。
10. 写审计。
11. 保存数据。
12. 推送 cashout。
13. 返回玩家最新状态。
```

为什么取现前后都更新有效爆点：

```text
取现前要判断奖池是否已经要求更早爆炸。
取现后奖池减少、真人 open 金额也减少，奖池上限可能变化。
```

手动取现伪代码如下。

这段伪代码的意思是：服务器收到取现请求时自己算倍率，如果已经到爆点就直接爆炸。

```text
function manualCashout(playerId):
    player = 查找玩家

    如果 currentRound 不存在或 phase 不是 flying：
        报错：火箭还没飞

    bet = 找到玩家本局 open 下注
    如果没有 bet：
        报错：没有可取现下注

    updateEffectiveCrashMultiplier("manual-cashout")
    currentMultiplier = multiplierAt(当前服务器时间)
    updateEffectiveCrashMultiplier("manual-cashout")

    如果 currentMultiplier >= currentRound.crashMultiplier：
        finishRound()
        报错：火箭已爆炸

    cashoutBet(bet, currentMultiplier, "manual")
    updateEffectiveCrashMultiplier("manual-cashout")
    保存数据
    推送 cashout
```

## 25. 派彩计算逻辑

派彩必须统一计算。

变量说明：

```text
A = 下注金额，单位是分
M = 取现倍率
K = 取现倍率对应的两位整数
P = 派彩金额，单位是分
```

先把倍率转成两位整数。

中文解释：2.35x 转成 235，1.5x 转成 150。

公式如下。

```text
K = 四舍五入(M × 100)
```

然后算派彩。

中文解释：下注金额乘以倍率整数，再除以 100，最后向下取整。

公式如下。

```text
P = 向下取整(A × K ÷ 100)
```

例子：

```text
下注 A = 10000 分，也就是 100.00
倍率 M = 2.35
K = 235
P = 向下取整(10000 × 235 ÷ 100) = 23500 分
```

玩家本局净盈利：

```text
净盈利 = 派彩 - 下注金额
```

例子：

```text
派彩 235.00
下注 100.00
净盈利 135.00
```

取现函数要做这些事：

```text
1. 检查 bet.status 必须是 open。
2. 限制倍率不能小于 1，不能超过最大爆点。
3. 计算派彩。
4. bet.status 改成 cashed。
5. 记录取现方式 manual 或 auto。
6. 记录取现倍率。
7. 记录派彩。
8. 记录结算时间。
9. 如果是真人，奖池减少派彩，玩家余额增加派彩。
10. 如果是机器人，不改奖池，不改真实余额。
```

伪代码如下。

这段伪代码的意思是：同一笔 open 下注只能结算一次，真人才会影响余额和奖池。

```text
function cashoutBet(bet, multiplier, mode):
    如果 bet.status 不是 open：
        返回失败

    safeMultiplier = 限制 multiplier 在 1 到 maxCrashMultiplier
    K = 四舍五入(safeMultiplier × 100)
    payout = 向下取整(bet.amountCents × K ÷ 100)

    bet.status = cashed
    bet.cashoutMode = mode
    bet.cashoutMultiplier = safeMultiplier
    bet.payoutCents = payout
    bet.settledAt = 当前时间

    如果 bet 不是机器人：
        prizePoolCents -= payout
        player.balanceCents += payout

    返回 bet
```

## 26. 爆炸结算逻辑

当服务器当前倍率达到有效爆点，火箭爆炸。

爆炸判断公式如下。

变量说明：

```text
M = 当前服务器倍率
E = 当前有效爆点
```

公式如下。

```text
如果 M >= E，则爆炸
```

爆炸时要做：

```text
1. 把所有 open 下注标记为 lost。
2. phase 改成 crashed。
3. currentMultiplier 改成最终有效爆点。
4. crashedAt = 当前服务器时间。
5. nextRoundAt = crashedAt + 3000 毫秒。
6. 统计真人下注总额。
7. 统计真人派彩总额。
8. 计算平台盈亏。
9. 统计真人人数和机器人人数。
10. 保存回合历史。
11. 写审计日志。
12. 保存数据。
13. 推送 crash。
14. 给每个在线玩家推送自己的历史记录更新。
```

open 下注变 lost 的逻辑如下。

这段伪代码的意思是：没有取现的人，本局爆炸后都输掉。

```text
for bet in currentRound.bets:
    如果 bet.status == open:
        bet.status = lost
        bet.payoutCents = 0
        bet.cashoutMultiplier = null
        bet.settledAt = 当前时间
```

平台盈亏只算真人。

变量说明：

```text
B = 真人下注总额
P = 真人派彩总额
H = 平台盈亏
```

公式如下。

```text
H = B - P
```

如果 H 是正数，平台本局盈利。

如果 H 是负数，平台本局亏损。

机器人金额不能计入 B，也不能计入 P。

## 27. 爆炸后 3 秒停留

爆炸后不要马上开下一局。

服务器要设置 nextRoundAt。

变量说明：

```text
crashedAt = 爆炸时间
CRASH_HOLD_MS = 爆炸停留时间，建议 3000 毫秒
nextRoundAt = 下一局开始时间
```

公式如下。

```text
nextRoundAt = crashedAt + CRASH_HOLD_MS
```

在 crashed 阶段：

```text
玩家不能下注。
玩家不能取现。
前端显示爆炸结果。
服务器等待 nextRoundAt。
```

tick 中检查：

```text
如果 phase 是 crashed 且 当前时间 >= nextRoundAt：
    currentRound = null
    createRound()
```

## 28. 机器人局高飞逻辑

纯机器人局可以偶尔高飞。

这个逻辑只允许在本局没有真人下注时触发。

目的：

```text
让画面偶尔出现 100x 到 500x。
因为没有真人下注，所以不会产生真实赔付风险。
```

触发条件：

```text
1. 机器人功能开启。
2. 当前回合有下注。
3. 当前回合没有真人下注。
4. 本局还没检查过高飞。
5. 随机数命中高飞概率。
```

高飞概率公式如下。

变量说明：

```text
G = botOnlyHighFlightBps
P = 高飞概率
```

公式如下。

```text
P = G ÷ 10000
```

如果命中，就在高飞最小倍率和最大倍率之间随机一个爆点。

变量说明：

```text
Min = 高飞最小倍率
Max = 高飞最大倍率
H = 高飞爆点
```

公式如下。

```text
H = Min 到 Max 之间的随机两位小数
```

伪代码如下。

这段伪代码的意思是：只有纯机器人局才可能把爆点改成 100x 到 500x。

```text
function applyBotOnlyHighFlight():
    如果本局已经检查过：
        返回 false

    标记本局已经检查过

    如果机器人没开启：
        返回 false

    如果本局没有任何下注：
        返回 false

    如果本局有真人下注：
        返回 false

    chance = botOnlyHighFlightBps ÷ 10000

    如果 随机数 >= chance：
        返回 false

    highCrash = 高飞范围内随机倍率
    currentRound.randomCrashMultiplier = highCrash
    currentRound.crashMultiplier = highCrash
    currentRound.botOnlyHighFlight = true
    返回 true
```

新手引导的演示可以在前端做假数据，但完成状态必须存在服务器。

服务器要保存：

```text

```

玩家完成或跳过新手引导时，前端通知服务器。

服务器处理：

```text
1. 找到玩家。
2. 检查 completed 必须是 true。
3. 如果 tutorialCompletedAt 为空，写入当前时间。
4. 写审计。
```

## 31. 实时推送逻辑

服务器不要持续推送倍率。

原因：

```text
飞行中每几十毫秒推一次倍率非常占带宽。
倍率可以由前端根据 launchAt 和曲线公式自己显示。
服务器只需要推关键事件。
```

建议推送事件：

```text
snapshot：连接成功后推当前完整状态
round_start：新回合开始
bet_placed：有人下注
flight_start：火箭起飞
cashout：有人取现
crash：火箭爆炸
settings_updated：后台配置变更
player_update：某个玩家余额或设置变化
my_history：玩家自己的历史记录
pong：延迟检测响应
```

每条推送都带 serverTime。

中文解释：serverTime 用于前端同步服务器时间，不依赖玩家电脑本地时间。

消息结构可以是：

```text
{
    type: 事件类型,
    serverTime: 服务器当前时间,
    data: 事件数据
}
```

连接成功时服务器要推 snapshot。

snapshot 包括：

```text
服务器当前时间
公开配置
玩家公开数据
当前回合公开数据
历史爆点
玩家自己的历史
```

飞行中不持续推倍率，只在起飞时推：

```text
launchAt
curve 参数
```

前端自己算显示倍率。

如果前端发现状态对不上，可以重新拉一次完整状态。

## 32. 前端显示延迟 1 秒时服务器怎么处理

前端可以为了显示稳定，故意比服务器真实飞行晚 1 秒。

但服务器不延迟。

服务器起飞后，真实逻辑立刻开始。

中文解释：

```text
前端的 1 秒延迟只是画面效果。
服务器的爆炸、自动取现、手动取现判断都按真实 launchAt 计算。
```

如果前端显示延迟 1 秒，手动取现可能出现这种情况：

```text
玩家画面看到还没爆。
但请求到服务器时，服务器真实倍率已经达到爆点。
服务器会判定取现失败。
```

这是合理的，因为服务器必须按真实时间结算。

为了减少玩家受网络影响：

```text
1. 前端高延迟时提示使用 Auto Cashout。
2. Auto Cashout 必须由服务器执行。
3. 手动 Cash Out 不承诺以画面倍率成功。
```

## 33. 高延迟和服务器时间

服务器要提供时间同步能力。

HTTP 响应和 WebSocket 消息都可以带服务器时间。

前端用这个时间计算服务器当前时间。

前端不能直接用玩家电脑时间判断游戏。

原因：

```text
玩家电脑时间可能快几分钟。
玩家电脑时间可能慢几分钟。
玩家可以手动改系统时间。
浏览器切后台后定时器可能不准。
```

延迟检测可以通过 ping/pong。

流程如下：

```text
1. 前端记录发送 ping 的本地性能时间。
2. 服务器收到 ping 后立刻返回 pong，并带 serverTime。
3. 前端收到 pong 后计算往返时间 RTT。
4. 如果 RTT > 1000 毫秒，显示高延迟提醒。
```

服务器只需要回 pong，不需要把 ping 当游戏操作。

后台最少要支持：

```text
查看后台可见爆点
查看奖池余额
查看真人下注总额
查看真人派彩总额
查看平台盈亏
查看真人人数
查看机器人人数
修改下注参数
修改爆点参数
修改曲线参数
修改机器人参数
手动设置奖池
调整玩家余额
强制爆炸
暂停和恢复
清理平台盈亏统计
清理回合记录
查看审计日志
```

后台修改配置时，要做：

```text
1. 读取请求参数。
2. 对每个参数做类型校验。
3. 对每个参数做范围限制。

7. 检查机器人下注最小间隔不能大于最大间隔。

9. 保存配置。
10. 写审计。
11. 推送 settings_updated。
```

如果后台调整奖池，必须立刻更新当前回合有效爆点。

```text
设置新奖池余额
updateEffectiveCrashMultiplier("admin-prize-pool")
保存数据
```

开发版后台可以免密码。

生产版后台必须有：

```text
登录

```

## 36. 强制爆炸逻辑

后台强制爆炸只适合测试或紧急处理。

它不能绕过奖池上限。

强制爆炸流程：

```text
1. 检查当前有回合。
2. 检查当前回合不是 crashed。
3. 读取管理员指定倍率。
4. 如果没指定倍率，就使用当前倍率。
5. 如果当前是 betting，当前倍率按 1.00。
6. 计算当前允许的最大强制倍率。
7. 强制倍率不能低于当前倍率。
8. 强制倍率不能高于奖池能承受的倍率。
9. 设置 randomCrashMultiplier 和 crashMultiplier。
10. 标记 forced = true。
11. 如果当前还在 betting，先 startFlying。
12. 立即 finishRound。
13. 写审计。
14. 保存数据。
```

当前允许的最大强制倍率：

```text
如果有真人 open 下注：
    最大强制倍率 = min(后台最大爆点, 奖池上限倍率)
否则：
    最大强制倍率 = 后台最大爆点
```

这样做的原因：

```text
即使管理员手动操作，也不能让奖池承担不了的赔付发生。
```

## 37. 暂停和恢复逻辑

暂停的含义是：不要再开新局。

建议逻辑：

```text
paused = true 时：
    如果没有当前回合，不创建新回合。
    如果当前回合正在进行，可以让它自然结束。
    当前回合结束后停住。
```

恢复时：

```text
paused = false
如果没有当前回合：
    createRound()
推送 settings_updated
```

暂停和恢复都要写审计。

后台清理平台盈亏时，不一定要删除回合。

可以用偏移量实现。

中文解释：历史回合还在，但统计从现在开始重新计算。

伪代码如下。

这段伪代码的意思是：把当前统计值取反写到偏移量里，让展示结果变成 0。

```text
current = 当前总下注、总派彩、总盈亏

metricOffsets.totalBet -= current.totalBet
metricOffsets.totalPayout -= current.totalPayout
metricOffsets.houseProfit -= current.houseProfit
```

清理回合记录时：

```text
db.rounds = []
metricOffsets = 0
写审计
保存数据
```

调整玩家余额时：

```text
1. 找到玩家。
2. 把调整金额转成分。
3. 调整金额不能是 0。
4. 调整后余额不能小于 0。
5. 更新玩家余额。
6. 写审计。
7. 保存数据。
8. 推送玩家余额更新。
```

## 39. 数据保存和恢复

开发版可以使用 JSON 文件。

生产版建议使用数据库。

无论用什么，都要保证：

```text
下注扣款和记录下注必须一起成功。
取现加款和记录取现必须一起成功。
爆炸结算和保存回合必须一起成功。
后台调整必须可审计。
```

如果用 JSON 文件，保存时不要直接覆盖原文件。

建议流程：

```text
1. 先写 db.json.tmp。
2. 写成功后 rename 成 db.json。
```

这样可以减少写到一半断电导致文件损坏的风险。

生产版必须使用事务。

例如下注：

```text
开始事务
锁定玩家余额
锁定当前回合
检查下注是否合法
扣玩家余额
插入下注记录
增加奖池
更新有效爆点
提交事务
```

如果中间任何一步失败：

```text
回滚事务
不要告诉玩家下注成功
```

## 40. 异常、熔断和维护

生产服务器必须有维护状态。

遇到这些情况应该进入维护：

```text
奖池余额为负数
玩家余额出现负数
配置参数非法
倍率算出 NaN
倍率算出 Infinity
有效爆点小于 1
数据库保存失败
扣款成功但下注记录失败
派彩成功但取现记录失败
回合状态缺失
当前回合数据损坏
服务器重启后无法确认飞行中回合
```

进入维护后：

```text
1. 停止创建新局。
2. 拒绝新下注。
3. 拒绝非必要操作。
4. 前端显示维护中。
5. 后台显示维护原因。
6. 管理员修复后手动恢复。
```

如果异常发生在 betting：

```text
可以取消本局，并退回真人已下注金额。
```

如果异常发生在 flying：

```text
必须按提前定义的规则处理。
建议生产上线前明确：继续按可验证状态结算，或者整局作废退款。
```

不要让服务器在已经知道数据错误的情况下继续开下一局。

## 41. 并发和重复请求

真实环境里，玩家可能重复点击按钮。

也可能网络重试导致同一个请求发送两次。

服务器必须防重复。

下注防重复：

```text
同一个玩家同一局只能有一笔下注。
```

取现防重复：

```text
只有 status = open 的下注可以取现。
取现成功后立刻改成 cashed。
第二次请求再来时，找不到 open 下注，不能重复派彩。
```

生产版还应该支持请求幂等。

中文解释：同一个操作 ID 重复提交，服务器返回同一个结果，而不是执行两遍。

建议每个下注和取现请求带 operationId。

伪代码如下。

这段伪代码的意思是：如果同一个 operationId 已经处理过，就直接返回上次结果。

```text
如果 operationId 已存在：
    返回已保存的处理结果
否则：
    执行操作
    保存 operationId 和结果
```

并发也要加锁。

至少要按这些维度加锁：

```text
玩家余额锁
当前回合锁
奖池锁
下注记录锁
```

如果用数据库，使用事务和行锁。

如果是单进程开发版，Node 事件循环能减少一部分并发问题，但只要有异步数据库或多进程部署，仍然必须加锁。

## 42. 安全注意事项

生产版本不要相信前端任何关键数据。

不能相信：

```text
前端传来的玩家 ID
前端传来的余额
前端传来的倍率
前端传来的爆点
前端传来的是否机器人
前端传来的取现时间
前端传来的后台身份
```

## 43. 服务器伪代码总流程

下面是一份完整伪代码，把前面的逻辑串起来。

这段伪代码的意思是：服务器启动后自动循环跑回合，玩家操作通过下注和取现函数进入，但所有结果都由服务器状态决定。

```text
启动服务器：
    加载配置
    加载数据
    如果数据损坏：
        进入维护或备份后重建
    如果没有暂停也没有维护：
        createRound()
    每 50 毫秒执行 tick()

tick():
    now = 当前服务器时间

    如果 maintenance：
        返回

    如果 currentRound 不存在：
        如果 paused：
            返回
        createRound()
        返回

    如果 currentRound.phase == betting：
        placeDueBotBets(now)
        如果 now >= currentRound.bettingEndsAt：
            startFlying()

    如果 currentRound.phase == flying：
        currentMultiplier = multiplierAt(now)
        currentRound.currentMultiplier = currentMultiplier
        processAutoCashouts(currentMultiplier)
        updateEffectiveCrashMultiplier("tick")
        如果 currentMultiplier >= currentRound.crashMultiplier：
            finishRound()

    如果 currentRound.phase == crashed：
        如果 now >= currentRound.nextRoundAt：
            currentRound = null
            createRound()

placeBet(playerId, amount, autoCashout):
    校验玩家
    校验当前阶段是 betting
    校验金额是允许筹码
    校验余额
    校验本局未下注
    扣余额
    奖池增加下注金额
    创建 open 下注
    updateEffectiveCrashMultiplier("human-bet")
    保存并推送

manualCashout(playerId):
    校验玩家
    校验当前阶段是 flying
    找到 open 下注
    updateEffectiveCrashMultiplier("manual-cashout")
    currentMultiplier = multiplierAt(当前服务器时间)
    如果 currentMultiplier >= crashMultiplier：
        finishRound()
        返回失败
    cashoutBet(bet, currentMultiplier, "manual")
    updateEffectiveCrashMultiplier("manual-cashout")
    保存并推送

processAutoCashouts(currentMultiplier):
    循环寻找已达到自动取现倍率的 open 下注
    按自动取现倍率从低到高处理
    每处理一笔都重新计算有效爆点

finishRound():
    open 下注全部 lost
    phase = crashed
    currentMultiplier = crashMultiplier
    crashedAt = 当前时间
    nextRoundAt = crashedAt + 3000
    统计真人金额
    保存历史
    推送 crash
```

## 45. 完整验收清单

### 回合

- 服务器启动后能自动创建回合。
- betting 到时间后自动进入 flying。
- flying 达到有效爆点后自动 crashed。
- crashed 停留 3 秒后自动下一局。
- 暂停时不会创建新局。

### 爆点

- 每局先判断 1.00x 即爆。
- 未命中即爆时使用 HMAC 随机数生成基础爆点。
- 平台抽水会影响基础爆点。
- 基础爆点会被最大爆点限制。
- 玩家端不公开本局爆点。

### 奖池

- 真人下注增加奖池。
- 真人取现减少奖池。
- 机器人不影响奖池。
- 有真人 open 下注时，会计算奖池上限。
- 有效爆点等于基础爆点和奖池上限中较小值。
- 奖池不足时通过降低有效爆点控制风险。
- 不因为奖池不足拒绝合法下注。
- 不因为奖池不足阻止合法取现。

### 倍率

- 倍率只由服务器时间和 launchAt 决定。
- 20x 前使用前段曲线。
- 20x 后使用指数曲线。
- 倍率向下保留两位小数。
- 不出现 NaN。
- 不出现 Infinity。

### 下注

- 只有 betting 可以下注。
- 下注金额必须是筹码档位。
- 下注金额不能低于最小下注。
- 下注金额不能高于最大下注。
- 余额不足不能下注。
- 同一玩家同一局只能下注一次。
- 下注成功后立即扣余额。
- 下注成功后推送玩家余额更新。

### 手动取现

- 只有 flying 可以取现。
- 只有 open 下注可以取现。
- 取现倍率由服务器收到请求时计算。
- 不使用前端传来的倍率。
- 已达到爆点时取现失败并爆炸。
- 同一笔下注不能重复取现。

### 自动取现

- 自动取现由服务器执行。
- 自动取现倍率必须小于有效爆点才成功。
- 达到目标倍率后按目标倍率派彩。
- 每处理一笔自动取现后重新计算有效爆点。
- 页面关闭、切后台、网络慢都不影响服务器自动取现。

### 派彩

- 派彩用整数分计算。
- 派彩等于下注金额乘以取现倍率。
- 真人派彩增加玩家余额。
- 真人派彩减少奖池。
- 机器人派彩不影响真实余额和奖池。

### 爆炸结算

- 爆炸时所有 open 下注变 lost。
- 已取现下注保持 cashed。
- 回合历史只统计真人下注和真人派彩。
- 机器人只统计人数，不进入平台盈亏。
- 爆炸后推送 crash。
- 爆炸后停留 3 秒。

### 机器人

- 机器人数量按后台范围随机。
- 机器人下注按间隔陆续发生。
- 机器人下注金额来自筹码档位。
- 机器人不显示 BOT 给玩家。
- 机器人自动取现实时发生。
- 纯机器人局可以按概率高飞。
- 有真人下注时不能触发纯机器人高飞。

### 推送

- WebSocket 连接后推 snapshot。
- 新局推 round_start。
- 下注推 bet_placed。
- 起飞推 flight_start。
- 取现推 cashout。
- 爆炸推 crash。
- 玩家余额变更推 player_update。
- 不持续推送每一帧倍率。
- 每条实时消息带 serverTime。

### 后台

- 后台能查看当前回合。
- 后台能查看奖池。
- 后台能修改下注档位和上限。
- 后台能修改爆点参数。
- 后台能修改曲线参数。
- 后台能修改机器人参数。
- 后台能手动设置奖池。
- 后台能强制爆炸，但不能超过奖池承受能力。
- 后台能暂停和恢复。
- 后台能调整玩家余额。
- 后台能清理平台盈亏统计。
- 后台能清理回合记录。
- 后台操作有审计日志。

### 异常和生产

- 数据保存失败不能返回成功。
- 扣款成功但下注记录失败必须回滚或补偿。
- 派彩成功但记录失败必须回滚或补偿。
- 奖池为负进入维护。
- 倍率 NaN 或 Infinity 进入维护。
- 配置非法进入维护。
- 生产环境使用数据库事务。
- 生产环境支持幂等请求。
- 生产后台必须有权限系统。

## 最终结论

制作 Rocket Crash 服务器，最核心的是把这几件事做严谨：

```text
服务器控制回合。
服务器生成爆点。
服务器计算倍率。
服务器处理取现。
服务器执行自动取现。
服务器用奖池压低有效爆点。
服务器结算真人金额。
机器人只做氛围。
前端只做显示。
异常时进入维护，不继续错误结算。
```

只要这些服务器逻辑完整，前端、后台、美术都可以围绕它扩展。
