# Rocket Crash 动态风控方案

## 1. 现有情况

当前服务器已经有这些逻辑。

### 平台优势

后台配置：

```text
houseEdgeBps = 150
```

意思是平台优势 1.5%。

公式：

```text
平台系数 = 1 - houseEdgeBps / 10000
```

普通爆点：

```text
基础爆点 = 平台系数 / (1 - 调整后随机数)
```

`houseEdgeBps` 越高，整体爆点越低。

### 1.00x 即爆

后台配置：

```text
instantCrashBps = 150
```

意思是 1.5% 概率直接 1.00x 爆炸。

公式：

```text
即爆概率 = instantCrashBps / 10000
```

如果本局随机数小于即爆概率：

```text
本局爆点 = 1.00x
```

### 奖池上限

当前已有奖池保护。

公式：

```text
奖池上限爆点 = 当前奖池余额 / 真人未取现下注总额
```

当前有效爆点：

```text
有效爆点 = min(随机基础爆点, 奖池上限爆点)
```

这能防止奖池赔不起，但还不够。

当前缺少：

```text
动态平台优势
单局最大亏损限制
平台赚多后的放水
奖池超额后的利润提取
不同风险状态的策略
```

## 2. 新方案目标

新方案不是设置死的每日盈利目标，而是让平台优势在区间内动态变化。

核心目标：

```text
平台亏损时收紧
平台收益不足时轻微收紧
平台正常时按基础参数
平台赚多时放水
奖池过高时提取超额利润
任何时候都不让单局打穿奖池
```

最终有效爆点统一用这个公式：

```text
有效爆点 = min(
  随机基础爆点,
  奖池上限爆点,
  单局最大亏损上限爆点,
  当前风险等级最大爆点,
  后台最大爆点
)
```

## 3. 动态平台优势

后台配置：

```text
基础平台优势
最低平台优势
最高平台优势
每局最大调整幅度
统计窗口
```

例如：

```text
基础平台优势 = 150 bps
最低平台优势 = 50 bps
最高平台优势 = 350 bps
每局最大调整 = 10 bps
统计窗口 = 最近 1000 局
```

统计窗口内：

```text
B = 真人下注总额
P = 真人派彩总额
G = 实际盈利 = B - P
E = 期望盈利 = B × 基础平台优势 / 10000
```

如果：

```text
G < E
```

说明平台赚得不够，平台优势逐步提高。

如果：

```text
G > E
```

说明平台赚多了，平台优势逐步降低。

调整必须平滑：

```text
下一局平台优势 =
当前平台优势 + 限制后的调整值
```

限制规则：

```text
每局最多只能上调或下调 maxStepBps
不能低于最低平台优势
不能高于最高平台优势
只影响新回合
```

## 4. 动态即爆

即爆也可以动态，但幅度要小。

原因：

```text
1.00x 即爆很容易被玩家感知。
变化过大会影响体验。
```

后台配置：

```text
基础即爆
最低即爆
最高即爆
每局最大调整
```

策略：

```text
平台亏损时，即爆小幅提高
平台赚多时，即爆小幅降低
正常状态回到基础值
```

建议范围：

```text
基础即爆 = 150 bps
最低即爆 = 20 bps
最高即爆 = 300 到 500 bps
```

## 5. 单局最大亏损限制

这是防止少数玩家一局拿走太多的核心规则。

后台配置：

```text
单局最大允许亏损 L
```

例如：

```text
L = 500
```

表示平台这一局最多允许净亏 500。

变量：

```text
B = 本局真人下注总额
P = 本局真人已派彩总额
O = 当前真人未取现下注总额
L = 本局最大允许亏损
```

公式：

```text
单局最大亏损上限爆点 = (B - P + L) / O
```

例子：

```text
B = 1000
P = 0
L = 500
O = 1000
```

```text
上限爆点 = (1000 - 0 + 500) / 1000 = 1.5x
```

如果所有真人在 1.5x 一起跳出：

```text
平台收 1000
平台赔 1500
平台净亏 500
```

刚好达到最大允许亏损。

## 6. 奖池保护

奖池保护继续保留。

公式：

```text
奖池上限爆点 = 可用奖池 / 真人未取现下注总额
```

建议增加奖池保留比例。

例如：

```text
奖池余额 = 100000
保留比例 = 20%
可用奖池 = 80000
```

公式：

```text
可用奖池 = 奖池余额 × (1 - 保留比例)
```

这样可以避免一次性把奖池打空。

## 7. 奖池超额提取

你提到的方案：

```text
奖池增长到设定金额后，扣掉固定金额或者百分比。
```

这个是合理的。

它本质是：

```text
奖池超过安全储备后，把超额部分转为平台利润或运营资金。
```

但必须加限制，不能随时随便扣。

### 推荐规则

后台配置：

```text
奖池目标金额 poolTarget
奖池最低保留金额 poolFloor
提取方式 fixed 或 percent
固定提取金额 poolSweepFixed
百分比提取 poolSweepBps
单次最大提取 poolSweepMax
提取间隔 poolSweepInterval
```

只允许提取超出目标的部分。

```text
超额奖池 = 奖池余额 - 奖池目标金额
```

如果超额奖池小于等于 0：

```text
不提取
```

固定金额提取：

```text
提取金额 = min(固定提取金额, 超额奖池, 单次最大提取)
```

百分比提取：

```text
提取金额 = min(超额奖池 × 提取百分比, 超额奖池, 单次最大提取)
```

提取后必须满足：

```text
奖池余额 - 提取金额 >= 奖池最低保留金额
```

### 什么时候提取

建议只在这些时机提取：

```text
回合结束后
没有真人 open 下注时
定时任务触发时
后台手动确认时
```

不建议在飞行中提取。

原因：

```text
飞行中提取会突然降低奖池上限，可能让当前局提前爆炸，玩家体验不好。
```

### 提取去哪里

提取金额建议记录到：

```text
平台利润账户
运营预算账户
放水预算池
```

推荐拆分：

```text
一部分进入平台利润
一部分进入放水预算池
```

例如：

```text
提取金额 10000
70% 进入平台利润
30% 进入放水预算池
```

这样平台赚多时可以有预算做放水。

## 8. 平台赚多了如何放水

平台赚多了不是强制某一局飞高。

推荐做法：

```text
降低平台优势
降低即爆概率
提高单局最大亏损预算
提高风险等级最大爆点
使用放水预算发奖励
```

### 放水预算

平台超额盈利：

```text
超额盈利 = 实际盈利 - 期望盈利
```

如果超额盈利大于 0：

```text
可放水预算 = 超额盈利 × 放水比例
```

例如：

```text
超额盈利 = 10000
放水比例 = 30%
可放水预算 = 3000
```

放水预算可以来自：

```text
超额盈利
奖池超额提取的一部分
运营手动注入
```

放水不能一次性用完。

```text
每局最多消耗放水预算的固定比例
```

例如：

```text
每局最多消耗 5%
```

## 9. 不同情况的策略

### 情况 A：平台正常

条件：

```text
实际盈利接近期望盈利
奖池健康
没有大额风险集中
```

策略：

```text
使用基础平台优势
使用基础即爆
使用标准下注上限
使用标准最大爆点
保留奖池上限
保留单局亏损上限
```

### 情况 B：平台赚得不够，但没有亏

条件：

```text
实际盈利 > 0
实际盈利 < 期望盈利
```

策略：

```text
平台优势小幅提高
即爆不变或小幅提高
单局最大亏损预算小幅降低
最大下注小幅降低
最大爆点一般不动
```

### 情况 C：平台轻度亏损

条件：

```text
实际盈利 < 0
亏损小于奖池 2%
```

策略：

```text
平台优势提高到中档
即爆小幅提高
单局最大亏损预算降低 30%
最大爆点降低到 20x 或 30x
下注上限降低 10% 到 20%
```

### 情况 D：平台中度亏损

条件：

```text
亏损达到奖池 2% 到 5%
```

策略：

```text
平台优势提高到高档
即爆提高到中档
单局最大亏损预算降低 50%
最大爆点降低到 10x
关闭大额筹码
下注上限降低 30% 到 50%
```

### 情况 E：平台严重亏损

条件：

```text
亏损超过奖池 5%
```

策略：

```text
平台优势接近最高值
即爆接近最高允许值
单局最大亏损预算接近 0
最大爆点降低到 5x 或 2.5x
只保留低额筹码
必要时暂停新局
```

### 情况 F：平台赚多了

条件：

```text
实际盈利 > 期望盈利
```

策略：

```text
平台优势逐步降低
即爆逐步降低
单局最大亏损预算提高
最大爆点适当提高
启用放水预算
```

### 情况 G：平台赚很多

条件：

```text
超额盈利明显
奖池健康
放水预算充足
```

策略：

```text
平台优势降到低档
即爆降到低档
最大爆点提高到放水档
单局最大亏损预算提高
发放透明奖励
每局限制放水预算消耗
```

### 情况 H：奖池不足

条件：

```text
奖池上限爆点过低
```

策略：

```text
有效爆点被奖池上限压低
降低下注上限
关闭大额筹码
严重时暂停新局
后台提示补充奖池
```

### 情况 I：奖池超过目标金额

条件：

```text
奖池余额 > 奖池目标金额
```

策略：

```text
回合结束后提取超额部分
可固定金额提取
可百分比提取
提取后不得低于最低保留金额
记录提取日志
部分进入平台利润
部分进入放水预算池
```

### 情况 J：大额下注集中

条件：

```text
真人未取现下注总额快速增大
```

策略：

```text
单局亏损上限爆点自动降低
奖池上限爆点自动降低
下一局降低最大下注
必要时关闭大额筹码
```

### 情况 K：多人同倍率自动取现

条件：

```text
很多玩家设置相同 Auto Cashout
```

策略：

```text
提前计算这一批潜在赔付
同倍率自动取现按同批处理
不要出现同倍率有人成功有人失败
风险上限要覆盖整批赔付
```

### 情况 L：只有机器人

条件：

```text
本局没有真人下注
```

策略：

```text
机器人不计入奖池
机器人不计入盈亏
可以高飞
可以提高高飞概率做氛围
```

只要有真人下注：

```text
禁用机器人高飞
```

### 情况 M：服务器异常

条件：

```text
奖池为负
倍率 NaN
爆点 Infinity
数据库保存失败
核心参数错误
```

策略：

```text
进入维护
停止新局
拒绝新下注
后台显示原因
人工修复后恢复
```

## 10. 风险等级

建议分 7 个状态。

```text
R0 正常
R1 收益不足
R2 轻度亏损
R3 中度亏损
R4 严重亏损
W1 轻度放水
W2 强放水
```

每个状态对应：

```text
平台优势
即爆概率
最大爆点
最大下注
单局最大亏损预算
是否启用放水
是否允许奖池提取
```

## 13. 迭代顺序

### 第一步：只做统计

```text
统计实际盈利
统计期望盈利
统计盈利偏差
后台展示
不影响游戏
```

### 第二步：单局亏损上限

```text
新增单局最大亏损配置
有效爆点加入单局亏损上限
后台显示限制原因
```

### 第三步：风险等级

```text
按收益和奖池状态分级
不同等级控制最大爆点和最大下注
```

### 第四步：动态平台优势

```text
平台优势按统计结果平滑调整
只影响新回合
```

### 第五步：动态即爆

```text
即爆按风险状态小幅调整
只影响新回合
```

### 第六步：放水预算

```text
超额盈利生成放水预算
赚多时降低平台优势和即爆
提高单局亏损预算
限制每局预算消耗
```

### 第七步：奖池超额提取

```text
奖池超过目标金额后
在回合结束或无真人 open 注单时提取
固定金额或百分比
提取后不得低于最低保留金额
记录日志
```

## 14. 最终方案

最终有效爆点：

```text
有效爆点 = min(
  随机基础爆点,
  奖池上限爆点,
  单局最大亏损上限爆点,
  当前风险等级最大爆点,
  后台最大爆点
)
```

平台赚少了：

```text
提高平台优势
轻微提高即爆
降低单局亏损预算
```

平台亏了：

```text
降低最大爆点
降低下注上限
降低单局亏损预算
严重时暂停
```

平台赚多了：

```text
降低平台优势
降低即爆
提高最大爆点
提高单局亏损预算
启用放水预算
```

奖池太高：

```text
回合结束后提取超额部分
部分进入平台利润
部分进入放水预算
```

奖池太低：

```text
压低有效爆点
降低下注上限
严重时暂停新局
```
