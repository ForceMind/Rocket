## 1. 核心原则

所有风控只统计真实玩家。

机器人只用于前端氛围，不计入平台盈亏，不计入 RTP，不计入奖池，不计入回合真实输赢。

Rocket 是多人同局游戏。正常公共局里，所有真实玩家必须看到同一个爆点，不能给不同真实玩家设置不同真实爆点。

如果某个用户个人 RTP 过高，不能主动为他创建或安排单独回合，也不能因为他影响公共局。

只有当某一局自然只有这个高 RTP 用户一个真实玩家时，才启用个人高 RTP 风控。

这里的“自然只有一个真实玩家”指的是：比如深夜服务器上只有他一个真实用户下注，其他展示出来的参与者都是机器人。

这样做的原因是：

- 不会影响其他真实玩家。
- 不会出现同一局不同真实玩家爆点不同的问题。
- 后端结算和前端展示都更简单。

高 RTP 用户单人局的核心规则：

- 提高 1.00x 即爆概率。
- 最大爆点限制在 2.50x 以内。
- 用户仍然可以正常下注、正常取现。
- 如果用户在爆点前取现，服务器正常结算。
- 不能在用户已经成功取现后再拒绝结算。

## 3. RTP 计算规则

RTP 是玩家返还率。

玩家下注越多，返奖越多，RTP 越高。

平台想要长期盈利，RTP 通常应该低于 100%。

### 3.1 今日 RTP

今日 RTP = 今日真实返奖总额 / 今日真实下注总额。

用整数基点保存：

```text
今日RTP基点 = floor(今日真实返奖总额 * 10000 / 今日真实下注总额)
```

示例：

- 今日真实下注总额是 100000。
- 今日真实返奖总额是 96000。
- 今日 RTP = 96000 / 100000 = 96%。
- 保存为 9600。

### 3.2 本周 RTP

本周 RTP = 本周真实返奖总额 / 本周真实下注总额。

```text
本周RTP基点 = floor(本周真实返奖总额 * 10000 / 本周真实下注总额)
```

### 3.3 个人生命周期 RTP

个人生命周期 RTP = 用户生命周期真实返奖总额 / 用户生命周期真实下注总额。

```text
个人生命周期RTP基点 = floor(用户生命周期真实返奖总额 * 10000 / 用户生命周期真实下注总额)
```

### 3.4 个人净输赢

个人净输赢 = 用户生命周期真实返奖总额 - 用户生命周期真实下注总额。

```text
个人净输赢 = 用户生命周期真实返奖总额 - 用户生命周期真实下注总额
```

结果大于 0，代表用户当前总体赢钱。

结果小于 0，代表用户当前总体输钱。

## 4. RTP 风控参数

### 4.1 平台级参数

| 参数 | 示例 | 说明 |
| --- | ---: | --- |
| 目标RTP基点 | 9600 | 目标 RTP 是 96.00% |
| 今日RTP允许波动基点 | 2000 | 今日 RTP 允许上下 20 个百分点 |
| 本周RTP允许波动基点 | 500 | 本周 RTP 允许上下 5 个百分点 |
| 基础平台优势基点 | 400 | 基础平台优势是 4.00% |
| 基础即爆概率基点 | 300 | 默认 1.00x 即爆概率是 3.00% |
| 最大即爆概率基点 | 5000 | 即爆概率最高不超过 50.00% |
| 后台最大爆点 | 50000 | 最大展示到 500.00x |
| 强收紧最大爆点 | 250 | 强收紧时最大 2.50x |
| 单局最大亏损金额 | 50000 | 单局最多允许平台净亏 500.00 |

如果目标 RTP 是 9600：

```text
今日RTP下限 = 9600 - 2000 = 7600
今日RTP上限 = 9600 + 2000 = 11600
本周RTP下限 = 9600 - 500 = 9100
本周RTP上限 = 9600 + 500 = 10100
```

对应含义：

- 今日 RTP 低于 76%，说明今天平台赚得偏多。
- 今日 RTP 高于 116%，说明今天平台返奖偏多。
- 本周 RTP 低于 91%，说明本周平台赚得偏多。
- 本周 RTP 高于 101%，说明本周平台返奖偏多。

| 个人高RTP三级 | 20000 | 生命周期 RTP 超过 200% |

## 5. 每局服务器流程

每局服务器按下面顺序执行。

1. 检查服务器是否处于维护状态。
2. 检查后台参数是否合法。
3. 检查奖池余额是否低于保底。
4. 接收真实玩家下注。
5. 识别每个真实玩家的个人 RTP 等级。
6. 识别高 RTP 用户，但不改变正常等待和匹配逻辑。
7. 统计今日 RTP 和本周 RTP。
8. 根据今日 RTP、本周 RTP 决定平台风控模式。
9. 根据平台风控模式计算本局平台优势和即爆概率。
10. 如果本局只有一个真实玩家，且这个真实玩家是高 RTP 用户，叠加个人高 RTP 即爆概率，并把最大爆点限制为 2.50x。
11. 生成随机爆点。
12. 计算奖池承受能力爆点上限。
13. 计算单局最大亏损爆点上限。
14. 取所有爆点限制里的最小值，得到最终爆点。
15. 回合起飞。
16. 服务器根据时间计算当前倍率。
17. 服务器自动执行自动取现。
18. 服务器接收用户手动取现请求。
19. 如果取现请求到达服务器时，服务器倍率小于最终爆点，则结算成功。
20. 如果服务器倍率已经达到或超过最终爆点，则结算失败。
21. 爆炸后停留展示。
22. 写入真实玩家回合记录。
23. 更新今日 RTP、本周 RTP、个人 RTP、奖池余额。
24. 检查是否需要奖池超额扣除。
25. 进入下一局。

## 6. 今日 RTP 和本周 RTP 判断

后端先算 RTP 区间。

```text
今日RTP下限 = 目标RTP基点 - 今日RTP允许波动基点
今日RTP上限 = 目标RTP基点 + 今日RTP允许波动基点

本周RTP下限 = 目标RTP基点 - 本周RTP允许波动基点
本周RTP上限 = 目标RTP基点 + 本周RTP允许波动基点
```

再判断状态：

```text
如果 今日RTP < 今日RTP下限，则今日状态 = 偏低
如果 今日RTP > 今日RTP上限，则今日状态 = 偏高
否则 今日状态 = 正常

如果 本周RTP < 本周RTP下限，则本周状态 = 偏低
如果 本周RTP > 本周RTP上限，则本周状态 = 偏高
否则 本周状态 = 正常
```

本周状态优先级高于今日状态。

原因是今日数据波动大，本周数据更能代表平台真实收益状态。

## 7. 不同 RTP 状态下的策略

### 7.1 今日正常，本周正常

策略：

- 使用基础平台优势。
- 使用基础即爆概率。
- 使用正常爆点分布。
- 不额外收紧。
- 不额外放水。

### 7.2 今日偏高，本周正常

说明：

- 今天玩家赢得偏多。
- 但本周还没有失控。

策略：

- 轻微提高平台优势。
- 轻微提高即爆概率。
- 降低高倍爆点概率。
- 降低单局最大亏损金额。

### 7.3 今日偏低，本周正常

说明：

- 今天平台赚得偏多。
- 但本周还正常。

策略：

- 轻微降低平台优势。
- 轻微降低即爆概率。
- 提高中倍爆点概率。
- 适当提高单局最大亏损金额。

### 7.4 本周偏高

说明：

- 本周玩家总体赢得偏多。
- 不管今天是否正常，都要优先收紧。

策略：

- 提高平台优势。
- 提高即爆概率。
- 降低高倍爆点概率。
- 降低风控最大爆点。
- 降低单局最大亏损金额。
- 暂停放水预算。

### 7.5 本周偏低

说明：

- 本周平台赚得偏多。
- 需要让 RTP 回升。

策略：

- 降低平台优势。
- 降低即爆概率。
- 提高中倍和高倍爆点概率。
- 提高单局最大亏损金额。
- 开启放水预算。

### 7.6 今日偏高，本周偏高

说明：

- 今天和本周都返奖偏多。
- 这是最强收紧状态。

策略：

- 明显提高平台优势。
- 明显提高即爆概率。
- 明显降低高倍爆点概率。
- 最大爆点可以临时限制到 2.50x。
- 单局最大亏损金额降到最低档。

### 7.7 今日偏低，本周偏低

说明：

- 今天和本周平台都赚得偏多。
- 这是最强放水状态。

策略：

- 明显降低平台优势。
- 明显降低即爆概率。
- 提高中高倍爆点概率。
- 提高单局最大亏损金额。
- 使用放水预算。

### 7.8 今日偏高，本周偏低

说明：

- 今天玩家赢得多。
- 但本周平台仍然赚得多。

策略：

- 不进入强收紧。
- 使用基础模式或轻度放松模式。
- 控制单局极端亏损即可。

### 7.9 今日偏低，本周偏高

说明：

- 今天平台赚得多。
- 但本周玩家总体赢得偏多。

策略：

- 不进入强放水。
- 使用基础模式或轻度收紧模式。
- 允许今天继续修复本周偏高 RTP。

## 8. 个人 RTP 风控

个人 RTP 风控用于识别生命周期内已经明显赢钱的用户。

个人 RTP 风控不是为了改变公共局里所有人的爆点。

如果用户个人 RTP 过高，后端不能主动为他创建或安排单独回合。

只有当本局真实玩家自然只有他一个人时，才对这一局提高即爆概率并限制最大爆点。

如果本局还有其他真实玩家，个人 RTP 不能改变这一局的公共爆点。

### 8.1 个人 RTP 生效条件

个人 RTP 风控必须同时满足下面条件才生效：

- 用户生命周期真实下注总额大于等于个人 RTP 最小下注样本。
- 用户生命周期真实局数大于等于个人 RTP 最小局数样本。
- 用户生命周期 RTP 大于等于个人高 RTP 阈值。
- 用户生命周期净赢大于等于个人净赢触发金额。

只满足 RTP 高，但下注样本太小，不生效。

只满足 RTP 高，但净赢金额很小，不生效。

只满足净赢金额高，但 RTP 正常，可以只记录观察，不启用单人高 RTP 风控。

### 8.2 个人 RTP 等级

| 等级 | 条件 | 处理 |
| --- | --- | --- |
| 正常 | 样本不足，或 RTP 没超过阈值 | 按普通规则进入当前回合 |
| 一级高 RTP | RTP 超过一级阈值，净赢达到触发额 | 如果本局只有他一个真实玩家，轻度提高即爆概率，最大爆点 2.50x |
| 二级高 RTP | RTP 超过二级阈值，净赢达到触发额 | 如果本局只有他一个真实玩家，中度提高即爆概率，最大爆点 2.50x |
| 三级高 RTP | RTP 超过三级阈值，净赢达到触发额 | 如果本局只有他一个真实玩家，重度提高即爆概率，最大爆点 2.50x |

## 9. 高 RTP 用户单人局规则

高 RTP 用户单人局不是服务器主动分配出来的回合。

它只是一种自然发生的状态。

例如深夜服务器上只有这个高 RTP 用户一个真实玩家下注，这一局就属于高 RTP 用户单人局。

如果同一局里还有其他真实玩家，即使其中一个用户个人 RTP 很高，也不能对这一局启用个人高 RTP 爆点限制。

### 9.1 单人局判断规则

后端在起飞前统计本局真实玩家数量。

机器人不算真实玩家。

判断逻辑：

```text
如果 本局真实玩家数量 == 1
并且 这个真实玩家是高RTP用户
并且 启用单人高RTP风控 == true：
    本局启用单人高RTP风控
否则：
    本局不启用单人高RTP风控
```

高 RTP 用户下注时，仍然进入正常等待队列。

服务器不需要把他主动隔离到另一个房间。

服务器只在本局起飞前，根据这一局最终真实玩家数量判断是否启用单人高 RTP 风控。

### 9.2 单人局即爆概率

单人高 RTP 风控生效时，本局即爆概率在平台即爆概率基础上增加。

```text
本局即爆概率 = 平台当前即爆概率 + 个人高RTP即爆增加值
```

最终不能超过后台配置的最大即爆概率：

```text
本局即爆概率 = min(本局即爆概率, 最大即爆概率)
```

示例：

- 平台当前即爆概率是 3%。
- 个人高 RTP 即爆增加值是 20%。
- 最大即爆概率是 50%。
- 那么本局即爆概率是 23%。

### 9.3 单人局最大爆点

单人高 RTP 风控生效时，本局最大爆点固定限制在 2.50x 以内。

后端用整数倍率保存：

```text
个人高RTP最大爆点 = 250
```

最终爆点必须满足：

```text
最终爆点 <= 250
```

如果随机算法抽到 8.00x，最终最多只能是 2.50x。

如果奖池限制只能承受到 1.80x，最终爆点就是 1.80x。

最终爆点永远取最小限制。

## 10. 爆点生成流程

后端生成爆点时按下面顺序执行。

### 10.1 确定本局即爆概率

先拿到平台当前即爆概率。

平台当前即爆概率由今日 RTP、本周 RTP 和当前风控模式决定。

如果本局命中单人高 RTP 风控，再增加个人高 RTP 即爆概率。

```text
本局即爆概率 = 平台当前即爆概率

如果 本局命中单人高RTP风控：
    本局即爆概率 = 本局即爆概率 + 个人高RTP即爆增加值

本局即爆概率 = min(本局即爆概率, 最大即爆概率)
```

### 10.2 先判断是否 1.00x 即爆

后端生成一个 0 到 9999 的随机整数。

如果随机整数小于本局即爆概率，则本局 1.00x 即爆。

```text
随机数 = 0 到 9999 的整数

如果 随机数 < 本局即爆概率：
    随机爆点 = 100
```

示例：

- 本局即爆概率是 300。
- 随机数范围是 0 到 9999。
- 随机数小于 300 的概率是 3%。
- 所以 1.00x 即爆概率是 3%。

### 10.3 未即爆时生成普通随机爆点

如果没有命中 1.00x 即爆，再按平台爆点分布生成普通随机爆点。

平台优势越高，高倍爆点越少。

平台优势越低，高倍爆点越多。

这一步得到的只是随机爆点，不是最终爆点。

### 10.4 计算所有爆点上限

后端需要同时计算：

- 后台最大爆点。
- 当前 RTP 风控模式最大爆点。
- 奖池承受能力爆点。
- 单局最大亏损爆点。
- 个人高 RTP 最大爆点。

如果本局没有命中单人高 RTP 风控，个人高 RTP 最大爆点不参与计算。

### 10.5 得到最终爆点

最终爆点取所有限制里的最小值。

```text
最终爆点 = min(
    随机爆点,
    后台最大爆点,
    当前RTP风控模式最大爆点,
    奖池承受能力爆点,
    单局最大亏损爆点,
    个人高RTP最大爆点
)
```

如果没有命中单人高 RTP 风控：

```text
最终爆点 = min(
    随机爆点,
    后台最大爆点,
    当前RTP风控模式最大爆点,
    奖池承受能力爆点,
    单局最大亏损爆点
)
```

## 11. 奖池承受能力限制

奖池限制的作用是：如果当前还没取现的真实玩家都在某个倍率取现，奖池必须付得起。

### 11.1 可用奖池

奖池不能全部拿来赔付，必须保留保底金额。

```text
可用奖池 = 当前奖池余额 - 奖池保底余额 - 本局已返奖金额
```

如果可用奖池小于等于 0，游戏进入维护或强制低爆点模式。

### 11.2 未取现真实下注额

```text
未取现真实下注额 = 本局仍然未取现的真实玩家下注金额之和
```

机器人下注不参与计算。

### 11.3 奖池承受能力爆点

```text
奖池承受能力爆点 = floor(可用奖池 * 100 / 未取现真实下注额)
```

示例：

- 可用奖池是 100000。
- 未取现真实下注额是 20000。
- 奖池承受能力爆点 = floor(100000 * 100 / 20000) = 500。
- 代表奖池最多承受到 5.00x。

如果未取现真实下注额为 0，说明没有真实玩家还在火箭上，奖池承受能力不限制爆点。

## 12. 单局最大亏损限制

单局最大亏损限制的作用是：即使奖池足够，也不能让一局亏太多。

### 12.1 本局当前平台盈亏

```text
本局当前平台盈亏 = 本局真实下注总额 - 本局已返奖金额
```

结果为正，代表平台当前盈利。

结果为负，代表平台当前亏损。

### 12.2 单局亏损还能承受多少

```text
单局剩余可亏金额 = 单局最大亏损金额 + 本局当前平台盈亏
```

如果本局当前平台已经盈利，剩余可亏金额会变大。

如果本局当前平台已经亏损，剩余可亏金额会变小。

### 12.3 单局亏损爆点

```text
单局亏损爆点 = floor(单局剩余可亏金额 * 100 / 未取现真实下注额)
```

如果未取现真实下注额为 0，说明没有真实玩家还在火箭上，单局亏损不限制爆点。

最终爆点不能超过单局亏损爆点。

## 13. 自动取现结算

自动取现必须由服务器执行。

前端只负责展示和提交用户设置。

服务器在每局飞行过程中，根据服务器时间计算当前倍率。

如果用户开启自动取现，并且当前服务器倍率大于等于用户设置的自动取现倍率，同时当前服务器倍率小于最终爆点，则服务器自动结算成功。

```text
如果 用户开启自动取现
并且 当前服务器倍率 >= 用户自动取现倍率
并且 当前服务器倍率 < 最终爆点：
    自动取现成功
```

用户手动取现时，以请求到达服务器时的服务器倍率为准。

不是以前端显示倍率为准。

```text
如果 请求到达服务器时的服务器倍率 < 最终爆点：
    手动取现成功
否则：
    手动取现失败
```

前端可以比服务器延迟 1 秒展示，用来减少用户看到火箭已经飞过爆点后才收到爆炸消息的问题。

但结算永远以服务器为准。

## 14. 平台赚多后的放水

平台赚多，主要表现是今日 RTP 或本周 RTP 低于下限。

放水不是直接送钱，而是让游戏在一段时间内更容易出现较好的结果。

放水方式：

- 降低平台优势。
- 降低即爆概率。
- 提高中倍爆点概率。
- 提高高倍爆点概率。
- 提高单局最大亏损金额。
- 增加返水或活动奖励。

放水优先级：

1. 本周 RTP 低于下限，优先放水。
2. 今日 RTP 低于下限，本周正常，轻度放水。
3. 今日低、本周高，不进入强放水。

放水不能突破奖池保底。

放水不能突破单局最大亏损限制。

单人高 RTP 风控局不参与放水。

## 15. 奖池超额扣除

奖池增长到目标金额以上后，可以扣掉固定金额或百分比。

只能扣超过目标的部分。

不能把奖池扣到低于目标金额。

不能把奖池扣到低于保底金额。

### 15.1 超额计算

```text
奖池超额 = 当前奖池余额 - 奖池目标余额
```

如果奖池超额小于等于 0，不扣除。

### 15.2 固定金额扣除

```text
本次扣除金额 = min(固定扣除金额, 奖池超额, 单次最大扣除金额)
```

### 15.3 百分比扣除

```text
本次扣除金额 = min(奖池超额 * 扣除比例 / 10000, 奖池超额, 单次最大扣除金额)
```

### 15.4 扣除时机

只能在一局结束后扣除。

不能在火箭飞行中扣除。

不能在有未结算真实玩家时扣除。

### 15.5 扣除资金去向

建议拆成两部分：

- 一部分进入平台利润。
- 一部分进入放水预算。

## 16. 自动维护和熔断

出现下面情况，服务器进入维护状态。

- 奖池余额小于 0。
- 奖池余额低于保底金额。
- 参数为空。
- 参数不是数字。
- 平台优势小于 0。
- 平台优势大于允许最大值。
- 即爆概率小于 0。
- 即爆概率大于最大即爆概率。
- 最大爆点小于 1.00x。
- 个人高 RTP 最大爆点小于 1.00x。
- 生成的随机爆点不是有效数字。
- 生成的最终爆点不是有效数字。
- 生成的最终爆点小于 1.00x。
- 数据库读写失败。
- 回合结算失败。
- 服务器时间异常。

维护状态处理：

- 不接受新下注。
- 如果回合还没有起飞，取消本局并退回真实玩家下注。
- 如果回合已经起飞，按服务器最后可确认状态结算，然后停止开新局。
- 后台记录维护原因。
- 运营修复后手动恢复。

## 17. 推荐实现顺序

第一步：统计真实玩家数据。

- 今日 RTP。
- 本周 RTP。
- 个人生命周期 RTP。
- 个人净输赢。
- 机器人全部排除。

第二步：实现今日 RTP 和本周 RTP 风控档位。

- 正常。
- 轻度收紧。
- 强收紧。
- 轻度放水。
- 强放水。

第三步：实现奖池承受能力限制。

- 计算可用奖池。
- 计算未取现真实下注额。
- 计算奖池承受能力爆点。
- 最终爆点不能超过奖池承受能力爆点。

第四步：实现单局最大亏损限制。

- 计算本局当前平台盈亏。
- 计算单局剩余可亏金额。
- 计算单局亏损爆点。
- 最终爆点不能超过单局亏损爆点。

第五步：实现单人高 RTP 风控。

- 用户下注前计算个人 RTP 等级。
- 不改变用户正常等待和匹配逻辑。
- 起飞前统计本局真实玩家数量。
- 如果本局只有一个真实玩家，且该真实玩家是高 RTP 用户，则启用单人高 RTP 风控。
- 单人高 RTP 风控局可以显示机器人。
- 单人高 RTP 风控局提高即爆概率。
- 单人高 RTP 风控局最大爆点限制到 2.50x。

第六步：实现放水预算。

- 本周 RTP 偏低时优先放水。
- 今日 RTP 偏低且本周正常时轻度放水。
- 放水不能突破奖池保底和单局亏损限制。

第七步：实现奖池超额扣除。

- 奖池超过目标后，只扣超额部分。
- 扣除动作只能在回合结束后执行。
- 扣除后不能低于目标金额和保底金额。

第八步：实现维护熔断。

- 参数异常自动维护。
- 奖池异常自动维护。
- 爆点异常自动维护。
- 数据库异常自动维护。

## 最终后端规则

公共局使用今日 RTP、本周 RTP、奖池、单局亏损共同控制最终爆点。

个人高 RTP 不直接影响公共局。

个人高 RTP 用户不会被主动安排到单独回合。

只有当本局自然只有一个真实玩家，且该真实玩家是高 RTP 用户时，才启用单人高 RTP 风控。

单人高 RTP 风控局可以显示机器人，但机器人不计入任何真实统计。

单人高 RTP 风控局提高 1.00x 即爆概率。

单人高 RTP 风控局最大爆点限制在 2.50x 以内。

最终爆点永远取所有限制里的最小值。

用户取现是否成功，永远以请求到达服务器时的服务器倍率为准。

自动取现必须由服务器执行，不能依赖前端。
