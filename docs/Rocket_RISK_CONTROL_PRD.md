# Rocket 智能风控引擎 (Risk Control Engine) - PRD 规范

本系统致力于通过智能且平滑的干预手段，保障平台资金的长线稳定健康，同时为玩家提供自然、无感、刺激的飞行体验。本次风控重构全面实现了动态的“九宫格矩阵化”调控，并支持精细到每种情况的后台参数配置。

---

## 1. 风控大盘资金核心逻辑

### 1.1 主奖池 (Prize Pool)
- **概念**：平台所有玩家下注汇总的基础资金池。
- **流转**：玩家输掉的钱进入奖池，玩家赢走的钱从奖池扣除。
- **溢出与清理机制**：系统设有后台配置的 **目标奖池界线**。当主奖池累积超过此金额时，系统会自动将超出的部分进行抽水清理。清理出的资金会按照后台配置的 **放水池分流比例**（如 30%）注入放水预算池，剩余部分则直接成为平台纯利润。

### 1.2 放水预算池 (Water Budget)
- **概念**：由主奖池外溢资金累积而来的专项资金池，专用于系统处于“放水模式”时的超额赔付支撑。
- **动态倍率上限 (硬控兜底)**：在进入放水局时，为了确保放水绝不动用主奖池进行超额让利，系统会预先计算本局的理论极限赔付倍率：`(放水预算池余额 + 本局真人总下注) / 本局真人总下注`。该比值将直接取代配置中的最大爆点，作为该局**生成随机爆点时的硬控上限**。
- **消耗规则**：若放水局玩家群体整体盈利（总提现 > 总下注），则超出下注额的净利润**全部由放水预算池扣除，主奖池仅负责抵扣下注额本金**。若放水局玩家整体依然亏损，亏损金额正常落入主奖池，放水池余额不变。

## 2. 周期监控与准入门槛

### 2.1 滚动周期监控
风控引擎摒弃了每天固定时间清零的方式，转而采用更加精准的**滚动周期计算 (Rolling Metrics)**：
- **24 小时大盘与个人 RTP**：系统通过回溯过去 24 小时的小时分桶数据，精确计算平台大盘以及单个玩家的 24 小时真实 RTP。
- **7 天大盘 RTP**：回溯过去 168 小时的总数据，作为判定长线资金走势的“主导指标”。

### 2.2 RTP 状态三档划分
根据当前算出的 RTP 值与后台配置的警戒线比对，系统会将 24h 和 7d 的大盘状态划分为三个区间：
- **高 (平台亏损)**：`RTP > 收紧警戒线 (默认 100%)`
- **正常 (平稳阶段)**：`放水警戒线 (默认 90%) <= RTP <= 收紧警戒线 (默认 100%)`
- **低 (平台大赚)**：`RTP < 放水警戒线 (默认 90%)`

### 2.3 多人局准入门槛 (Thresholds)
为了防止在业务冷清或半夜无人时，少量的几局下注被长线 RTP 放大，导致系统进入错误的极端放水或收紧，新增了**触发门槛**：
- 系统后台可配置：**24h门槛局数、24h门槛金额、7天门槛局数、7天门槛金额**。
- **规则**：如果在多人局中，上述任何一个门槛未达标，系统将直接挂起风控矩阵，退回执行最基础的“正常”配置。

### 2.4 小额娱乐免除 (Small Bet Exemption)
- **触发条件**：多人局且本局总下注额低于后台配置的免控阈值（如 <= 1000 金币）。
- **处理机制**：全部无视 RTP 状态和单人防守，直接判定为正常娱乐对局，应用基础的“正常”调控逻辑，提供原生体验。

## 3. 风控决策树与执行引擎

本系统在每局下注截止瞬间，会严格按照以下优先级进行判断：

### 优先级一：纯机器人局
若当前局**没有任何真人玩家下注**，系统跳过所有的 RTP 统计与矩阵推算。
- 系统判定是否触发 **机器人高飞逻辑**（由配置概率决定）。
- 若触发，随机生成超高倍数；若未触发，则应用基础的正常配置。由于没有真人抽水，这完全是为了造势。

### 优先级二：单人局胜率异常限制 (Personal Defender)
若当前局**全场仅有 1 名真人玩家下注**，触发个人防守检测：
- **触发条件**：该玩家的 24 小时滚动 RTP 超过后台配置的危险值（如 120%）。
- **处理机制**：在该局游戏中启动独立防守策略。后台可以独立配置该模式下的三大参数。默认情况下，将该局的即爆概率拔高至 15%，平台优势提高至 3%，并且**最大随机爆点硬控为 2.50x**（配合微调扣减，玩家几乎无法突破）。

### 优先级三：小额免除或准入门槛拦截
若为多人局，先检查是否触发小额免除（见 2.4）或未达到门槛（见 2.3）。若被拦截，统一下发“正常 (Normal)”模式的配置参数。

### 优先级四：风控九宫格矩阵 (Risk Matrix)
当多人局满足所有门槛，系统将根据 **7天状态 (周)** 和 **24小时状态 (日)** 进行组合查表，得出 9 种可能的服务器状态。每种状态的三大核心变量（即爆概率、平台优势、最大爆点）均**可在后台独立配置**：

| 大方向 (7天状态) | 微调方向 (24h状态) | 服务器状态名 | 特点说明 |
|:---------- |:----------- |:-------- | :---- |
| 高 (平台亏损) | 高 (平台亏损) | **极强收紧 (HH)** | 平台大失血，通过高即爆与极低上限强行止损。 |
| 高 (平台亏损) | 正常 | **强收紧 (HN)** | 长线亏损但今日平稳，适度收紧。 |
| 高 (平台亏损) | 低 (平台盈利) | **轻收紧 (HL)** | 长线亏损但今日盈利，减弱收紧力度。 |
| 正常 | 高 (平台亏损) | **轻收紧 (NH)** | 长线平稳但今日亏损，小幅防守。 |
| 正常 | 正常 | **正常 (NN)** | 大盘完全平稳，一切应用标准基线。 |
| 正常 | 低 (平台盈利) | **轻放水 (NL)** | 长线平稳且今日盈利，开始释放红利池放水。 |
| 低 (平台盈利) | 高 (平台亏损) | **正常 (LH)** | 长线盈利但今日已亏损，暂停放水切回正常。 |
| 低 (平台盈利) | 正常 | **轻放水 (LN)** | 长线盈利且今日平稳，温和放水。 |
| 低 (平台盈利) | 低 (平台盈利) | **强放水 (LL)** | 长短线均暴利，动用放水预算进行高倍率福利派发。 |

> [!NOTE]
> **放水状态的特殊性**：在 NL、LN、LL 这三个放水状态下，后台配置的“最大爆点”将被**忽略**，系统会强制使用放水预算池算出的安全极限值作为生成上限。

## 4. 倍率生成与微调打磨

### 4.1 核心调控三要素
在得出任何一种状态后，系统将这 3 个参数灌入核心计算器，**不作其他暴力干涉**：
1. **即爆概率 (Instant Crash Bps)**：开局直接等于 1.00x 的概率。
2. **平台优势 (House Edge Bps)**：底层算法的抽水率，天然压低高倍率出现的频次。
3. **最大随机爆点 (Max Multiplier)**：限制该局能够生成的最大倍数。

### 4.2 去规律化微调扣减 (Micro-Deduction)
为了防止在设定了上限（如单人防守的 2.50x，或收紧时的 5.0x）时，大量对局正好生成出带有强烈规律感的整倍数，导致外挂能够摸清天花板：
- **全局统一扣减**：对于生成的**所有最终爆点**，系统都会统一在末尾随机扣掉 `0.01x ~ 0.09x`。
- **安全保障**：这种微调是最后一步执行，系统严格保证无论怎么扣减，爆点都**最小止步于 1.00x**，绝不会跌穿。
- **效果**：最大倍数设置 2.50x，玩家最终看到的往往是 2.45、2.48、2.41 等毫无规律的数字，隐藏了系统的干预痕迹。

---

## 5. 安全兜底刚性切断
如果在游戏飞行途中由于部分玩家意外逃脱等原因导致单次赔付过大，系统依然保有最后一道底线防线：
- **单次赔付上限截断**：由后台配置的防线数值（如 500.00）。当当前总提现额度飞越单局限额时，系统在此触发强行坠毁。
