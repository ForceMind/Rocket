# Rocket Crash 动态风控系统产品需求文档 (PRD)

## 1. 概述
本次需求旨在为 Rocket Crash 游戏引入一套**完整的动态风控系统**，通过多维度的 RTP (Return to Player) 监控和动态参数调整，平衡玩家体验与平台收益。保留现有的“奖池上限爆点”及“机器人隔离”功能，新增 9 项核心风控机制。

---

## 2. 核心机制设计

### 2.1 周期性 RTP 监控
系统通过实时监控不同周期的 RTP 数据，识别平台盈亏趋势，为风控模式切换提供依据。
- **本周 RTP（主导趋势）**：目标 `96%`，用于判断平台整体盈亏方向，优先级最高。
  - **低 (平台赢)**：`< 91%`
  - **正常**：`91% - 101%`
  - **高 (平台亏)**：`> 101%`
  *(生效门槛：本周下注额 ≥ 50w 游戏金币 且 局数 ≥ 1000 局)*
- **今日 RTP（短期修正）**：目标 `96%`，用于平抑单日异常波动。
  - **低 (平台赢)**：`< 76%`
  - **正常**：`76% - 116%`
  - **高 (平台亏)**：`> 116%`
  *(生效门槛：今日下注额 ≥ 10w 游戏金币 且 局数 ≥ 30 局)*
> **注**：未达生效门槛时，对应周期状态视为“样本不足”，不参与强判定。

### 2.2 动态风控参数
根据系统所处的风控模式，动态下发以下参数干预游戏：
1. **动态平台优势**：平台亏损时提高优势（压低整体爆点），盈利时降低优势。
2. **动态即爆概率 (1.00x)**：亏损时提高即爆率，盈利时降低。最直接的止损手段。
3. **普通爆点隐性扣点**：在生成的普通随机爆点上，隐蔽扣除 `0.01x - 0.05x`（扣除后不低于 1.00x），增加平台边际收益。

### 2.3 极端场景限制
1. **单次总赔付上限**：防止单局出现巨额赔付击穿利润。
   - `单次上限爆点 = 后台配置的单次总赔付上限 / 本局真人总下注`
2. **个人高 RTP 单人局风控**：防止运气极佳的“欧皇”玩家在单人游戏时持续获利。
   - 触发条件：本局仅 1 名真人 + 玩家个人 RTP ≥ 120% + 净赢 ≥ 1000 游戏金币（及局数/流水门槛）。
   - 惩罚措施：即爆概率额外 `+20%`。**重要说明：此处的 2.50x 并非在结果上强行截断，而是临时修改了后台配置的最大爆点，缩小了随机数的映射关系上限**（为防规律被识破，实际映射上限为 2.50 随机减去 0 ~ 1.50），使爆点曲线依然自然。本局若有其他真人参与则不生效。

### 2.4 奖池与放水池机制
- **资金分流**：当奖池超过目标金额时，超额部分按比例拆分为 **“平台利润”** 与 **“放水预算”**。
- **放水条件**：今日或本周 RTP 过低（平台赚多）且有放水预算。
- **放水表现**：降低平台优势、降低即爆概率、放开爆点限制，提升玩家体验。

## 3. 核心决策与执行逻辑

### 3.1 风控模式决策矩阵
**本周状态优先级高于今日状态。** 系统根据两者组合，匹配出 6 种最终模式：

| 本周状态 (主导) | 今日状态 (辅助) | 最终模式 | 策略说明 |
| :--- | :--- | :--- | :--- |
| **高 (平台亏)** | 高 (亏损) | **极强收紧** | 整体与短期双亏损，强力止损 |
| **高 (平台亏)** | 正常/不足 | **强收紧** | 整体亏损，重点收紧 |
| **高 (平台亏)** | 低 (盈利) | **轻收紧** | 整体亏损但短期回落，温和收紧 |
| 正常/不足 | **高 (平台亏)** | **轻收紧** | 仅短期亏损，轻微回调 |
| 正常/不足 | 正常/不足 | **正常** | 无需干预，正常运行 |
| 正常/不足 | **低 (平台赢)** | **轻放水** | 短期盈利，适当让利玩家 |
| **低 (平台赢)** | 高 (亏损) | **正常** | 整体盈利但今日已超额返奖，停放水 |
| **低 (平台赢)** | 正常/不足 | **轻放水** | 整体盈利，温和放水 |
| **低 (平台赢)** | 低 (盈利) | **强放水** | 整体与短期双双盈利，大力放水 |

### 3.2 模式对应参数对照表
| 风控模式 | 平台优势 | 即爆概率 | 最大爆点上限 | 是否消耗放水预算 |
| :--- | :--- | :--- | :--- | :--- |
| **正常** | 1.5% | 1.5% | 无额外限制 | 否 |
| **轻收紧** | 2.5% | 2.5% | 20.00x | 否 |
| **强收紧** | 5.0% | 8.0% | 5.00x | 否 |
| **极强收紧** | 8.0% | 15.0% | 2.50x (随机减去 0~1.50) | 否 |
| **轻放水** | 1.0% | 1.0% | 无额外限制 | 是 |
| **强放水** | 0.5% | 0.5% | 无额外限制 | 是 |

### 3.3 单局最终爆点计算流程 (核心算法)
每局游戏的最终爆点 `FinalCrash` 并非简单的多值取小截断，其核心在于**修改随机数的映射上限**：

1. **确定生成上限**：系统会对比以下几项，取**最小值**作为本局随机数生成的**映射关系上限**（这会缩小随机数曲线的分布范围，而非事后硬截断）：
   - `admin_max`：后台配置的全局最大爆点。
   - `rtp_risk`：风控模式带来的爆点上限（如极强收紧对应的 2.50x 浮动上限）。
   - `personal_solo_rtp`：个人高 RTP 单人局限制（如生效则为 2.50x 浮动上限）。
2. **生成初始随机爆点**：
   - 判断是否即爆，若即爆直接为 `1.00x`。
   - 若未即爆，则基于设定的**映射上限**和平台优势生成自然平滑的随机爆点，并扣除 `0.01~0.05` 的隐性扣点。
3. **资金安全硬性截断**：
   将生成的初始随机爆点与以下资金安全限制取**最小值 (Min)**：
   - `round_payout_cap`：单次总赔付上限爆点。
   - `pool_cap`：现有奖池上限爆点。

系统需记录决定最终爆点的 **限制原因 (Reason)**，以便于后期数据追踪。若多项计算值相同，优先级为：`个人单人局 > 单次赔付 > 奖池上限 > 风控模式 > 后台配置 > 自然随机`。

## 4. 后台及数据需求
需要丰富后台监控及报表功能，提供以下模块的支持：
1. **总览大盘**：实时展示今日/本周 RTP 及状态、当前生效的风控模式及核心参数、奖池与放水预算。
2. **回合报表**：记录每局参与的风控因子、各项爆点上限的计算结果、最终爆点及限制生效原因。
3. **用户报表**：新增用户个人 RTP 标签、个人局风控触发次数、单局最高盈利等反欺诈指标。
4. **奖池与风控日志**：记录资金池抽水与放水流向；记录风控模式和 RTP 状态的变更历史轴。
