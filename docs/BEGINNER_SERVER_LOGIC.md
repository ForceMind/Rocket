# Rocket Crash 服务器逻辑小白版

这份文档可以直接发给程序员。

目标是让程序员不看当前项目代码，也能按这个逻辑重新做一套 Rocket Crash 游戏服务，并接到自己的直播间里。

本文只讲服务器逻辑，不讲页面怎么画，也不设计具体 HTTP 路由。直播间怎么登录、怎么进房、怎么显示礼物、怎么显示弹幕，由接入方自己的直播系统负责。

## 1. 先记住一句话

Rocket Crash 的服务器是裁判。

前端和直播间只负责：

- 显示画面。
- 收玩家操作。
- 把玩家操作发给服务器。

服务器负责：

- 开局。
- 倒计时。
- 接受下注。
- 扣余额。
- 生成爆点。
- 计算当前倍率。
- 判断能不能取现。
- 自动取现。
- 判断爆炸。
- 派彩。
- 记录回合。

最重要的原则：

```text
所有钱、倍率、爆点、输赢，都以服务器为准。
```

前端显示的倍率只能看，不能用来结算。

玩家说自己在 2.50x 点了 Cash Out，也不能直接相信。服务器收到请求时是多少倍，就按服务器当时的倍率判断。

## 2. Rocket 服务在直播间里负责什么

Rocket 服务可以理解成直播间里的一个小游戏服务。

它不一定要管理直播间本身，但它必须管理游戏本身。

Rocket 服务负责：

- 维护每个直播间的 Rocket 回合。
- 保存玩家游戏余额，或者调用直播间钱包扣款加款。
- 处理玩家下注。
- 处理玩家取现。
- 处理自动取现。
- 控制机器人下注和取现。
- 控制奖池。
- 控制爆点。
- 推送游戏状态给直播间前端。

如果一个平台有多个直播间，每个直播间可以有一套独立游戏。

例如：

```text
直播间 A 有自己的当前回合、玩家列表、奖池、机器人。
直播间 B 也有自己的当前回合、玩家列表、奖池、机器人。
两个直播间互不影响。
```

如果 MVP 只做一个直播间，也可以先只做一个全局游戏。

## 3. 直播间系统需要提供什么

Rocket 服务接入直播间时，直播间系统至少要提供这些能力。

### 用户身份

Rocket 服务需要知道：

- 这个玩家是谁。
- 玩家在哪个直播间。
- 玩家是否登录。
- 玩家显示名是什么。

建议直播间传给 Rocket：

```text
roomId：直播间 ID
userId：直播间用户 ID
displayName：用户昵称
avatar：用户头像，可选
token：登录凭证
```

Rocket 服务必须验证 token，不能只相信前端传来的 userId。

### 钱包或积分

Rocket 有两种钱包方案。

方案一：Rocket 自己保存游戏余额。

优点：

- 实现简单。
- 游戏逻辑独立。
- 本地开发最方便。

缺点：

- 和直播间主余额不是同一套。
- 上生产时要考虑充值、提现、审计。

方案二：直播间系统提供钱包能力。

Rocket 每次下注时调用直播间钱包扣款。

Rocket 每次取现时调用直播间钱包加款。

优点：

- 直播间余额统一。
- 更接近生产。

缺点：

- 必须处理钱包调用失败。
- 必须处理重复请求。
- 必须处理事务。

如果接入真实直播间，建议生产版本用方案二。

### 实时消息通道

Rocket 服务需要把这些消息发给直播间前端：

- 新回合开始。
- 有人下注。
- 火箭起飞。
- 有人取现。
- 火箭爆炸。
- 下一局倒计时。
- 玩家余额变化。

可以用 WebSocket，也可以接入直播间已有的实时消息系统。

核心要求：

```text
消息要及时，但不要每 50 毫秒推一次倍率。
```

倍率可以让前端根据服务器给的起飞时间自己算。

服务器只推关键事件。

## 4. 最小可运行架构

最小可运行版本可以分成 7 个模块。

### 回合模块

负责一局一局地跑。

它知道：

- 当前是等待下注。
- 当前是飞行中。
- 当前是爆炸后停留。
- 什么时候开下一局。

### 下注模块

负责接收玩家下注。

它检查：

- 当前是不是等待下注阶段。
- 玩家余额够不够。
- 下注金额是不是允许的筹码。
- 玩家本局是不是已经下注过。

### 取现模块

负责玩家 Cash Out。

它检查：

- 当前是不是飞行阶段。
- 玩家本局有没有未取现的下注。
- 服务器当前倍率有没有到爆点。

### 自动取现模块

负责服务器帮玩家在指定倍率自动跳出。

它不能依赖前端。

只要服务器算到当前倍率达到玩家设置值，就自动结算。

### 爆点模块

负责生成本局基础爆点。

它会考虑：

- 1.00x 即爆概率。
- 随机数。
- 平台抽水。
- 最大倍率上限。

### 奖池模块

负责控制风险。

它会计算：

```text
当前奖池最多能赔到多少倍
```

如果奖池不够，服务器会降低本局有效爆点。

### 推送模块

负责把关键状态变化发给前端或直播间。

它推：

- 开局。
- 下注。
- 起飞。
- 取现。
- 爆炸。
- 余额变化。

它不持续推：

- 每一帧倍率。
- 每一帧火箭位置。

## 5. 需要保存哪些数据

下面不是数据库表设计，只是告诉程序员必须保存哪些东西。

### 玩家 Player

每个玩家至少要有：

```text
playerId：Rocket 内部玩家 ID
roomId：直播间 ID
userId：直播间用户 ID
displayName：用户昵称
maskedName：隐藏后的名字，例如 Jo**
balance：余额，如果钱包在 Rocket 内部
defaultAutoCashout：上次设置的自动取现倍率
tutorialCompletedAt：新手引导完成时间
createdAt：第一次进入时间
updatedAt：最后更新时间
```

如果钱包在直播间系统里，Rocket 可以不保存 balance，但仍然要保存本局下注、取现和回合记录。

### 回合 Round

每一局至少要有：

```text
roundId：回合 ID
roomId：直播间 ID
phase：当前阶段
createdAt：创建时间
bettingEndsAt：下注结束时间
launchAt：起飞时间
crashedAt：爆炸时间
nextRoundAt：下一局开始时间
randomCrashMultiplier：随机基础爆点
effectiveCrashMultiplier：最终有效爆点
currentMultiplier：服务器当前倍率
poolCapMultiplier：奖池能承受的最高倍率
poolCapped：是否被奖池压低爆点
forced：是否后台强制爆炸
botOnlyHighFlight：是否机器人局高飞
bets：本局所有下注
```

phase 建议只用这几个值：

```text
waiting：等待下注
flying：飞行中
crashed：已爆炸，等待下一局
maintenance：维护中
```

### 下注 Bet

每一笔下注至少要有：

```text
betId：下注 ID
roundId：回合 ID
roomId：直播间 ID
playerId：玩家 ID
isBot：是不是机器人
amount：下注金额
autoCashoutEnabled：是否开启自动取现
autoCashoutMultiplier：自动取现倍率
status：下注状态
placedAt：下注时间
cashedOutAt：取现时间
cashoutMultiplier：取现倍率
payout：派彩金额
profit：净盈利
```

status 建议：

```text
open：已下注，未取现，未爆炸
cashed_out：已取现
lost：已爆炸，未取现，输掉
cancelled：异常取消
```

### 奖池 Prize Pool

奖池至少要保存：

```text
roomId：直播间 ID
balance：奖池余额
updatedAt：更新时间
```

如果多个直播间共用一个总奖池，也可以不按 roomId 拆分。但对新项目来说，每个直播间独立奖池更容易理解和排查。

### 配置 Settings

配置要能后台修改。

至少包括：

```text
bettingDurationMs：等待下注时间
crashHoldMs：爆炸后停留时间
chipTiers：允许的下注筹码
minBet：最小下注
maxBet：最大下注
defaultPlayerBalance：新玩家初始余额
instantCrashBps：1.00x 即爆概率
houseEdgeBps：平台抽水
maxCrashMultiplier：最大爆点
curveEarlyTargetMs：前段到 20x 的时间
curveEarlyPower：前段曲线指数
curveLateSpeedMs：20x 后增长速度
botsEnabled：是否启用机器人
botMinCount：机器人最少数量
botMaxCount：机器人最多数量
botBetIntervalMinMs：机器人下注最小间隔
botBetIntervalMaxMs：机器人下注最大间隔
botMinBet：机器人最小下注
botMaxBet：机器人最大下注
botOnlyHighFlightBps：纯机器人局高飞概率
botOnlyHighFlightMin：高飞最小倍率
botOnlyHighFlightMax：高飞最大倍率
displayLagMs：前端显示延迟，建议 1000 毫秒
highLatencyMs：高延迟提醒阈值，建议 1000 毫秒
paused：是否暂停开新局
maintenance：是否维护中
```

## 6. 后台需要配置哪些参数

后台不是只给程序员看的，运营也要能理解。

每个参数都要有说明。

### 下注参数

```text
允许筹码：玩家只能下注这些档位，例如 10、50、100、500。
最小下注：低于这个金额不能下注。
最大下注：高于这个金额不能下注。
默认玩家余额：新玩家第一次进入时给多少余额。
```

### 回合参数

```text
等待下注时间：一局开始后，玩家有多久可以下注。
爆炸停留时间：爆炸后停留多久再开下一局，建议 3000 毫秒。
```

### 爆点参数

```text
1.00x 即爆概率：多少局会直接 1.00x 爆炸，单位 bps。
平台抽水：控制长期收益，单位 bps。
最大爆点：普通局最多允许飞到多少倍。
```

bps 是万分比。

```text
100 bps = 1%
150 bps = 1.5%
1000 bps = 10%
10000 bps = 100%
```

### 倍率曲线参数

```text
前段到 20x 的时间：从 1.00x 到 20.00x 大约用多久。
前段曲线指数：控制 20x 前的起步速度和加速感。
20x 后增长速度：控制超过 20x 后涨得快还是慢。
```

### 机器人参数

```text
机器人开关：是否启用机器人。
机器人最少数量：每局机器人下注人数下限。
机器人最多数量：每局机器人下注人数上限。
机器人下注间隔：机器人不是一起下注，而是按间隔陆续下注。
机器人下注范围：机器人每次下注的金额范围。
纯机器人高飞概率：只有机器人时，有多大概率飞到 100x 到 500x。
纯机器人高飞范围：高飞的最小和最大倍率。
```

### 奖池参数

```text
奖池余额：当前可赔付真人玩家的钱。
手动设置奖池：后台可以直接调整奖池。
清理回合记录：方便本地或运营重置数据。
清理平台盈亏：方便重新统计。
```

## 7. 一局游戏的完整服务器流程

完整流程如下。

```text
1. 服务器启动
2. 加载配置和数据
3. 检查是否维护中
4. 创建新回合
5. 生成本局基础爆点
6. 进入等待下注阶段
7. 玩家和机器人陆续下注
8. 每次真人下注后更新奖池和有效爆点
9. 倒计时结束，火箭起飞
10. 服务器按时间计算当前倍率
11. 服务器处理自动取现
12. 玩家可以手动取现
13. 服务器不断检查是否达到有效爆点
14. 达到爆点，火箭爆炸
15. 未取现玩家输掉
16. 记录回合结果
17. 爆炸画面停留 3 秒
18. 创建下一局
```

程序上可以有一个定时循环，比如每 50 毫秒或 100 毫秒跑一次。

这个循环做的事情：

```text
如果没有当前回合，就创建回合。
如果当前回合是 waiting，检查倒计时是否结束。
如果 waiting 到时间，就进入 flying。
如果当前回合是 flying，计算当前倍率，处理自动取现，判断爆炸。
如果当前回合是 crashed，检查 3 秒停留是否结束。
如果停留结束，就创建下一局。
```

## 8. 阶段一：创建新回合

创建新回合时，服务器要做这些事：

1. 生成 roundId。
2. 记录创建时间。
3. 计算下注结束时间。
4. 生成本局基础爆点。
5. 初始化本局下注列表为空。
6. 初始化当前倍率为 1.00。
7. 初始化阶段为 waiting。
8. 如果启用机器人，生成机器人下注计划。
9. 推送新回合开始消息。

创建回合时不要告诉玩家本局爆点。

玩家只需要知道：

- 新局开始了。
- 现在可以下注。
- 倒计时还有多久。

## 9. 阶段二：等待下注

等待下注阶段，玩家可以下注。

服务器处理下注时按这个顺序检查。

```text
1. 当前是不是 waiting 阶段。
2. 当前时间是否还没超过下注结束时间。
3. 玩家是否登录。
4. 玩家本局是否已经下注过。
5. 下注金额是否在允许筹码里。
6. 下注金额是否超过上限。
7. 玩家余额是否足够。
8. 自动取现倍率是否合法。
9. 扣玩家余额。
10. 如果是真人下注，奖池增加下注金额。
11. 记录下注。
12. 重新计算奖池能承受的爆点上限。
13. 重新计算本局有效爆点。
14. 推送有人下注消息。
```

注意：

```text
合法下注不应该因为奖池不足被拒绝。
奖池不足时，通过降低有效爆点控制风险。
```

例如：

玩家下注成功了，但因为奖池不够，火箭可能更早爆炸。

玩家不会知道这个原因。

## 10. 阶段三：火箭起飞

等待下注倒计时结束后，服务器进入 flying。

服务器要做：

```text
phase = flying
launchAt = 当前服务器时间
currentMultiplier = 1.00
推送起飞消息
```

前端可以显示 Starting Soon 1 秒。

但服务器不等这 1 秒。

服务器从 launchAt 开始就正常计算倍率。

这点非常重要：

```text
前端延迟只是显示效果。
服务器真实游戏已经开始。
```

## 11. 阶段四：飞行中

飞行中，服务器每次循环做这些事：

```text
1. 用服务器当前时间减去 launchAt，得到已飞行毫秒数。
2. 用倍率公式算出当前倍率。
3. 处理所有达到条件的自动取现。
4. 更新奖池爆点上限。
5. 更新有效爆点。
6. 判断当前倍率是否已经达到有效爆点。
7. 如果达到，就爆炸。
8. 如果没达到，继续飞。
```

注意顺序：

```text
先处理已经达到条件的自动取现，再判断爆炸。
```

原因：

如果玩家设置 Auto Cashout 2.00x，本局爆点是 2.10x，那么服务器算到 2.00x 时应该先帮玩家取现成功，而不是等到后面一起处理。

如果玩家设置 Auto Cashout 2.00x，本局爆点是 1.80x，那么玩家不会取现成功，因为火箭应该先爆炸。

## 12. 阶段五：玩家手动取现

玩家点击 Cash Out 后，前端向服务器发一个“我要取现”的请求。

服务器收到后，不看前端传来的倍率。

服务器自己算：

```text
当前服务器时间 - launchAt = 已飞行毫秒数
把已飞行毫秒数放进倍率公式 = 当前服务器倍率
```

然后检查：

```text
1. 当前是不是 flying。
2. 玩家本局是否有 open 状态的下注。
3. 当前倍率是否小于有效爆点。
4. 如果小于爆点，取现成功。
5. 如果已经达到或超过爆点，取现失败，本局爆炸或已经爆炸。
```

手动取现成功时：

```text
cashoutMultiplier = 当前服务器倍率
payout = 下注金额 × cashoutMultiplier
玩家余额增加 payout
奖池减少 payout
下注状态改成 cashed_out
推送取现成功消息
```

如果钱包在直播间系统里，取现成功时就调用直播间钱包加款。

必须保证同一笔下注只能取现一次。

## 13. 阶段六：服务器自动取现

自动取现是服务器自己做。

玩家下注时如果开启 Auto Cashout，比如设置 2.00x，服务器会把这个值保存在本局下注里。

飞行中每次循环检查：

```text
如果下注状态是 open
并且开启了 Auto Cashout
并且当前服务器倍率 >= 自动取现倍率
并且自动取现倍率 < 有效爆点
那么服务器按自动取现倍率结算
```

自动取现结算倍率建议用玩家设置的目标倍率。

例如：

玩家设置 2.00x。

服务器循环时当前倍率已经是 2.03x。

只要本局还没爆炸，玩家应该按 2.00x 自动取现，而不是 2.03x。

这样更公平，也更容易理解：

```text
玩家预约的是 2.00x，到了 2.00x 就跳。
服务器晚一点处理到，不应该让玩家多拿。
也不应该让玩家因为循环间隔损失。
```

## 14. 阶段七：火箭爆炸

服务器判断爆炸的规则：

```text
如果当前服务器倍率 >= 有效爆点，火箭爆炸。
```

爆炸时服务器要做：

```text
1. phase = crashed
2. crashedAt = 当前服务器时间
3. crashMultiplier = 有效爆点
4. 所有 open 状态下注改成 lost
5. 记录本局真人下注总额
6. 记录本局真人派彩总额
7. 记录真人人数和机器人人数
8. 保存回合记录
9. 推送爆炸消息
10. 设置 nextRoundAt = 当前时间 + 3000 毫秒
```

注意：

机器人金额不要计入平台盈亏。

真人金额才计入平台盈亏。

平台盈亏可以这样理解：

```text
平台盈亏 = 真人下注总额 - 真人派彩总额
```

如果结果是正数，平台本局赚。

如果结果是负数，平台本局亏。

## 15. 阶段八：停留 3 秒再开下一局

爆炸后不要马上清空画面。

服务器要让回合保持 crashed 状态 3 秒。

这样前端和直播间观众能看清楚：

- 爆点是多少。
- 谁赢了。
- 谁输了。
- 火箭爆炸效果。

3 秒后，服务器再创建下一局。

这 3 秒内：

- 玩家不能下注。
- 玩家不能取现。
- 前端显示爆炸结果。

## 16. 爆点怎么生成

爆点生成分三步。

```text
第一步：判断是否 1.00x 即爆。
第二步：计算随机基础爆点。
第三步：用奖池承受能力压低最终有效爆点。
```

### 第一步：1.00x 即爆

后台有一个参数：

```text
instantCrashBps
```

它表示 1.00x 即爆概率。

例如：

```text
instantCrashBps = 150
```

意思是：

```text
150 ÷ 10000 = 1.5%
```

每局生成一个 0 到 1 之间的随机数。

如果随机数小于 0.015，本局直接 1.00x 爆炸。

### 第二步：随机基础爆点

如果没有命中 1.00x 即爆，继续算基础爆点。

需要两个参数：

```text
random：0 到 1 之间的随机数
houseEdgeBps：平台抽水，单位 bps
```

先把平台抽水变成系数：

```text
平台系数 = 1 - houseEdgeBps ÷ 10000
```

例如：

```text
houseEdgeBps = 150
平台系数 = 1 - 150 ÷ 10000 = 0.985
```

基础爆点：

```text
基础爆点 = 平台系数 ÷ (1 - random)
```

然后做限制：

```text
如果基础爆点小于 1.01，就按 1.01。
如果基础爆点大于后台最大爆点，就按后台最大爆点。
倍率保留两位小数，向下取整。
```

向下取整的意思：

```text
2.349 变成 2.34
2.999 变成 2.99
```

不要四舍五入成更高倍率。

### 第三步：奖池限制

基础爆点还不是最终爆点。

服务器必须看奖池是否能承受真人玩家的潜在赔付。

最终有效爆点：

```text
有效爆点 = 基础爆点 和 奖池上限 中较小的那个
```

如果没有真人未取现下注，奖池上限可以按后台最大爆点。

## 17. 奖池怎么控制爆点

奖池是用来赔真人玩家的钱。

真人玩家下注时：

```text
奖池增加下注金额
```

真人玩家取现时：

```text
奖池减少派彩金额
```

机器人不影响奖池。

### 奖池上限怎么计算

服务器要随时知道：

```text
当前还有多少真人下注没有取现
```

把这些下注金额加起来，叫：

```text
真人未取现下注总额
```

奖池上限：

```text
奖池上限 = 当前奖池余额 ÷ 真人未取现下注总额
```

例如：

```text
当前奖池余额 = 10000
真人未取现下注总额 = 2000
奖池上限 = 10000 ÷ 2000 = 5
```

这表示：

如果所有还没跳出的真人玩家都在 5.00x 一起跳，奖池刚好赔完。

所以本局有效爆点不能超过 5.00x。

如果基础爆点是 12.00x：

```text
有效爆点 = 5.00x
```

如果基础爆点是 2.00x：

```text
有效爆点 = 2.00x
```

核心原则：

```text
奖池不够时，不是拒绝下注，也不是阻止取现。
奖池通过降低爆点控制风险。
```

## 18. 倍率怎么增长

倍率由服务器时间决定。

先算：

```text
已飞行毫秒数 = 当前服务器时间 - launchAt
```

然后把“已飞行毫秒数”放进倍率公式。

当前推荐用两段公式。

### 为什么分两段

20x 以前是最常用的游戏区间。

玩家大多数会在 1.20x、1.50x、2.00x、3.00x 这些位置纠结。

所以 20x 以前要更好控制节奏。

20x 以后是高倍率区间。

如果继续用前段公式，后期可能显得太慢。

所以分成：

```text
前段：1.00x 到 20.00x
后段：20.00x 以后
```

### 前段公式

后台配置：

```text
前段目标时间 = 35000 毫秒
前段曲线指数 = 2.4
```

先算进度：

```text
进度 = 已飞行毫秒数 ÷ 前段目标时间
```

进度限制在 0 到 1 之间。

再算弯曲后的进度：

```text
弯曲后的进度 = 0.02 × 进度 + 0.98 × 进度的前段曲线指数次方
```

如果前段曲线指数是 2.4，就是：

```text
弯曲后的进度 = 0.02 × 进度 + 0.98 × 进度的 2.4 次方
```

最后算倍率：

```text
前段倍率 = 1 + 19 × 弯曲后的进度
```

为什么乘 19：

```text
20.00x - 1.00x = 19
```

这条曲线的效果：

- 刚起飞不会太快。
- 也不会卡在 1.00x 太久。
- 越接近 20x 越快。

### 后段公式

超过前段目标时间后，进入后段。

后台配置：

```text
后段速度时间 = 12000 毫秒
```

后段倍率：

```text
后段倍率 = 20 × e 的 ((已飞行毫秒数 - 前段目标时间) ÷ 后段速度时间) 次方
```

e 是数学里的自然常数，大约是 2.71828。

大白话理解：

```text
超过 20x 后，用指数方式继续涨。
后段速度时间越小，涨得越快。
后段速度时间越大，涨得越慢。
```

### 倍率取两位小数

显示和判断时，倍率都应该统一为两位小数。

建议：

```text
倍率 = 向下取整(原始倍率 × 100) ÷ 100
```

例如：

```text
2.349 -> 2.34
2.999 -> 2.99
```

不要让不同地方有的四舍五入、有的向下取整。

## 19. 为什么前端可以自己显示倍率

飞行中如果服务器每 50 毫秒推一次倍率，带宽会很浪费。

更好的做法：

服务器只告诉前端：

```text
launchAt：服务器起飞时间
curveEarlyTargetMs：前段目标时间
curveEarlyPower：前段曲线指数
curveLateSpeedMs：后段速度时间
当前服务器时间
```

前端拿到这些，就可以自己算画面上的倍率。

这只是显示。

结算还是服务器算。

前端需要做服务器时间同步：

```text
服务器现在几点
前端收到消息时自己的性能时间是多少
两者算出偏移
之后用偏移估算服务器时间
```

不要用玩家电脑系统时间直接判断游戏。

玩家本地时间可能是错的。

## 20. 为什么不能按前端传来的倍率结算

因为前端不可信。

原因：

- 玩家电脑时间可能不准。
- 浏览器可能卡顿。
- 网络可能延迟。
- 页面切后台后计时器可能变慢。
- 前端代码可能被玩家修改。
- 玩家可以伪造请求。

所以 Cash Out 请求里最多只能告诉服务器：

```text
我要取现
```

不能相信：

```text
我在 3.25x 取现
```

正确方式：

```text
服务器收到取现请求时，自己按服务器时间算当前倍率。
```

如果服务器算出来还没爆，取现成功。

如果服务器算出来已经爆了，取现失败。

## 21. 机器人怎么做

机器人是为了直播间氛围。

机器人不能影响真实盈亏。

机器人下注流程：

```text
1. 每局开始时，根据配置决定机器人数量。
2. 生成机器人名字。
3. 给每个机器人安排下注时间。
4. 下注时间要分散在等待下注期间。
5. 到时间后，服务器把机器人下注加入本局列表。
6. 推送机器人下注消息。
```

机器人下注金额：

```text
必须来自筹码档位。
例如只能是 10、50、100、500。
```

机器人取现：

```text
每个机器人提前生成一个自动取现倍率。
飞行中达到这个倍率就显示机器人取现。
```

机器人金额规则：

```text
机器人下注不增加奖池。
机器人取现不减少奖池。
机器人不计入平台盈亏。
机器人不计入真实下注总额。
机器人可以计入本局显示人数。
```

机器人名字：

```text
前端显示隐藏名，例如 Ra**、Jo**。
不要显示 BOT。
```

## 22. 只有机器人时的高飞逻辑

如果一局没有真人下注，只有机器人，可以偶尔让火箭飞得很高。

目的：

- 直播画面更刺激。
- 让玩家看到 100x 到 500x 这种高倍率。
- 因为没有真人，所以不会产生真实赔付风险。

逻辑：

```text
1. 回合进入飞行前或飞行初期，检查本局是否只有机器人。
2. 如果有真人下注，不允许走高飞。
3. 如果只有机器人，按后台概率判断是否高飞。
4. 如果命中，把本局有效爆点设置到高飞范围内的随机值。
```

例如：

```text
高飞概率 = 800 bps = 8%
高飞范围 = 100x 到 500x
```

如果命中：

```text
本局爆点可能是 268.43x
```

注意：

```text
只要有一个真人下注，就不能用机器人高飞逻辑。
```

## 23. 直播间接入逻辑

接到直播间时，推荐按这个思路。

### 第一步：玩家进入直播间

直播间前端拿到登录态。

然后连接 Rocket 游戏。

Rocket 服务收到玩家信息后：

```text
1. 验证直播间 token。
2. 确认 roomId。
3. 确认 userId。
4. 查找或创建 Rocket 玩家。
5. 返回当前回合状态。
6. 返回玩家余额或钱包信息。
7. 返回玩家上次 Auto Cashout 设置。
8. 返回玩家是否完成新手引导。
```

### 第二步：玩家下注

玩家点击筹码和 Place Bet。

Rocket 服务：

```text
1. 验证玩家身份。
2. 验证玩家在这个 roomId。
3. 验证当前回合可以下注。
4. 验证金额合法。
5. 扣款。
6. 记录下注。
7. 推送下注消息给同直播间所有观众。
```

### 第三步：玩家取现

玩家点击 Cash Out。

Rocket 服务：

```text
1. 验证玩家身份。
2. 找到该玩家本局 open 下注。
3. 用服务器时间计算当前倍率。
4. 判断是否已经爆炸。
5. 如果没爆，结算派彩。
6. 推送取现消息。
```

### 第四步：回合结束

火箭爆炸后，Rocket 服务：

```text
1. 记录本局结果。
2. 推送爆炸消息。
3. 等待 3 秒。
4. 开下一局。
```

直播间前端只要订阅 Rocket 状态变化，就能显示游戏。

## 25. 高延迟怎么处理

前端要测玩家到服务器的延迟。

如果延迟超过 1000 毫秒，要提示：

```text
Your latency is high. Display may be delayed. Auto Cashout is recommended.
```

中文意思：

```text
你的延迟较高，画面可能不准，建议使用自动取现。
```

为什么要提示：

```text
前端显示比服务器慢。
玩家手动点 Cash Out 到服务器也需要时间。
如果网络太慢，玩家看到还没爆，但服务器可能已经爆了。
```

所以：

```text
网络差时，Auto Cashout 更可靠。
```

因为 Auto Cashout 是服务器执行，不需要等玩家点击消息传到服务器。

## 26. 新手引导服务器要记什么

新手引导不要只存在浏览器本地。

服务器要保存：

```text
tutorialCompletedAt
```

规则：

```text
如果玩家没有 tutorialCompletedAt，第一次进入时显示新手引导。
如果玩家完成或跳过，服务器记录时间。
以后再进来，不自动弹。
规则页面里可以手动重新播放。
```

新手引导用假数据，不影响真实回合和余额。

服务器不需要真的开一局教程局。

只需要记住玩家是否完成过。

## 28. 异常和维护状态

生产版本必须有维护状态。

遇到这些情况，不要继续开局：

```text
奖池余额为负数
核心配置不合法
倍率算出 NaN
倍率算出 Infinity
爆点小于 1
回合数据损坏
扣款失败
加款失败
数据库保存失败
服务器重启后无法恢复当前回合
```

进入维护后：

```text
1. 停止开新局。
2. 拒绝新下注。
3. 前端显示维护中。
4. 后台显示维护原因。
5. 等管理员修复后恢复。
```

如果异常发生在 waiting：

```text
可以取消本局，退回已下注玩家金额。
```

如果异常发生在 flying：

```text
需要按平台规则处理。
建议生产环境提前定义：按当前可验证状态结算，或者整局作废退款。
```

这部分必须和运营、法务、财务提前确认。

## 30. 验收清单

程序员做完后，按这份清单检查。

### 回合

- 能自动一局接一局。
- 等待下注有倒计时。
- 起飞时间由服务器记录。
- 爆炸后停留 3 秒再开下一局。
- 暂停时不再开新局。

### 下注

- 只能 waiting 阶段下注。
- 下注金额必须是筹码档位。
- 超过余额不能下注。
- 每个玩家每局只能下注一次。
- 真人下注会增加奖池。
- 机器人下注不会增加奖池。

### 取现

- 只能 flying 阶段取现。
- 手动取现按服务器收到请求时倍率。
- 前端传来的倍率不参与结算。
- 同一笔下注不能重复取现。
- 真人取现会减少奖池。
- 机器人取现不会减少奖池。

### 自动取现

- Auto Cashout 由服务器执行。
- 页面关闭或切后台不影响自动取现。
- 自动取现达到目标倍率后能成功结算。
- 爆点低于目标倍率时不会成功取现。
- 玩家上次设置的 Auto Cashout 倍率能保存。

### 爆点和奖池

- 先判断 1.00x 即爆。
- 再生成随机基础爆点。
- 再应用最大爆点限制。
- 再应用奖池上限。
- 奖池不足时通过降低有效爆点控制风险。
- 不因为奖池不足拒绝合法下注。
- 不因为奖池不足阻止合法取现。

### 倍率

- 倍率按服务器时间计算。
- 公式稳定，不出现 NaN。
- 公式稳定，不出现 Infinity。
- 倍率保留两位小数。
- 前端显示倍率不参与结算。

### 机器人

- 机器人陆续下注，不是起飞前一秒全部出现。
- 机器人金额不计入平台盈亏。
- 机器人金额不计入奖池。
- 玩家列表不显示 BOT。
- 只有机器人时才可能触发高飞。

### 直播间接入

- 玩家身份通过直播间 token 验证。
- 玩家和 roomId 绑定正确。
- 不同直播间数据隔离。
- 只给同一个直播间推送同一局消息。
- 断线重连后能拿到当前回合状态。

### 异常

- 奖池为负进入维护。
- 参数错误进入维护。
- 扣款失败不记录下注成功。
- 加款失败不记录取现成功，或有明确补偿机制。
- 数据保存失败不能继续假装成功。

## 最后总结

一个新的 Rocket 服务，只要抓住这几件事就不会跑偏：

```text
服务器是裁判。
前端只显示。
爆点不公开。
Cash Out 按服务器收到请求时倍率。
Auto Cashout 由服务器执行。
奖池通过有效爆点控制风险。
机器人只做氛围，不进真实盈亏。
飞行中不持续推倍率，前端按服务器时间自己显示。
异常时宁可维护，也不要继续错误结算。
```

这就是可以接入直播间的 Rocket Crash 服务器核心逻辑。
