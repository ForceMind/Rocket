## 游戏流程

1. 服务器启动后读取数据、恢复配置和历史状态。如果游戏没有暂停，服务器创建新回合。
2. 新回合进入下注阶段。服务器生成本局随机材料、随机爆点、有效爆点初始值和机器人下注计划。
3. 玩家在下注阶段选择筹码下注。真实玩家下注成功后，玩家余额减少，奖池余额增加，本局有效爆点立即重新计算。
4. 机器人在下注阶段按计划间隔陆续下注。机器人只影响展示和人数统计，不影响奖池和平台盈亏。
5. 下注倒计时结束后，服务器切换到飞行阶段，记录起飞时间，并固定本局飞行曲线参数。
6. 飞行阶段中，服务器用服务器当前时间和起飞时间计算当前倍率。前端可以用同样曲线显示动画，但不参与结算。
7. 如果玩家设置了自动取现，服务器在倍率达到目标且目标低于有效爆点时自动结算。
8. 如果玩家手动取现，服务器按请求到达服务器时的当前倍率结算，不使用前端传来的倍率。
9. 飞行过程中，服务器持续根据剩余未取现真实下注和奖池余额计算有效爆点。如果奖池承受能力低于随机爆点，火箭会在奖池可承受倍率处爆炸。
10. 当服务器当前倍率达到有效爆点时，火箭爆炸。未取现订单失败，已取现订单保持成功。
11. 爆炸后结果停留 3 秒。停留结束后，服务器清理当前回合并创建下一局。
12. 如果服务器发现奖池为负、参数异常、倍率异常、数据写入失败或结算风险失控，游戏自动进入维护状态，停止新下注和新回合，保留现场并等待修复。

## 1. 产品范围

Rocket Crash 是实时多人倍率下注游戏。每一局开始后，玩家在下注阶段选择一个筹码下注；火箭起飞后，倍率按服务器时间增长；玩家需要在火箭爆炸前取现。成功取现的玩家按取现倍率获得返还，未取现的下注在爆炸时归零。

本文档用于生产版本开发、测试、运营配置和风控验收。文档只描述产品规则、服务器流程、参数、数学计算和结算口径。

## 2. 玩法规则

1. 每局只有一个下注窗口，玩家只能在下注阶段下注。
2. 每个玩家每局最多下注一次。
3. 下注金额必须等于后台配置的某个筹码档位。
4. 火箭起飞后，倍率持续上升，玩家可以手动取现。
5. 玩家可以在下注时开启自动取现，并设置目标倍率。
6. 自动取现由服务器执行，不由前端执行。
7. 如果玩家在爆炸前取现，返还金额等于下注金额乘以取现倍率。
8. 如果玩家没有在爆炸前取现，本局下注损失。
9. 玩家不知道本局爆点，也不知道奖池如何影响爆点。
10. 前端只负责展示，结算以服务器为准。

## 3. 服务器核心原则

1. 服务器是唯一权威。爆点、当前倍率、下注、取现、奖池、余额和回合结算都由服务器决定。
2. 前端不能决定结算倍率。手动取现时，结算倍率取请求到达服务器时服务器计算出的倍率。
3. 前端不公开服务端种子、种子哈希、随机摘要、未爆炸前的爆点或任何可反推爆点的数据。
4. 奖池不足不能直接拒绝下注，也不能直接阻止取现。奖池风险通过动态降低有效爆点控制。
5. 机器人只用于营造活跃度。机器人金额不进入真实奖池、真实总下注、真实总返还或平台盈亏。
6. 真实玩家下注会增加奖池。真实玩家成功取现会减少奖池。
7. 自动取现目标只要低于有效爆点，服务器必须保证在爆点前结算。

## 4. 金额、倍率和概率口径

金额在服务器内部使用整数分保存。展示金额等于整数分除以 100。例如 1000 分展示为 10.00。

倍率保留两位小数。服务器计算当前倍率后，统一向下截断到两位小数。例如 2.349 显示和结算为 2.34x。

概率使用万分比配置。10000 表示 100%，150 表示 1.5%，800 表示 8%。

取现返还使用整数分计算：

| 公式名称 | 公式                     | 说明                                      |
| ---- | ---------------------- | --------------------------------------- |
| 倍率整数 | K = round(M × 100)     | M 是结算倍率，K 是两位小数倍率对应的整数。例如 2.35x 对应 235。 |
| 返还金额 | P = floor(A × K ÷ 100) | A 是下注金额分，P 是返还金额分，结果向下取整。               |

等价说法是，先把倍率转成两位小数对应的整数，再乘下注金额，最后除以 100 并向下取整。

示例：

- 下注金额是 1000 分。
- 结算倍率是 2.35x。
- K = round(2.35 × 100) = 235。
- P = floor(1000 × 235 ÷ 100) = 2350 分。

## 5. 完整服务器流程

### 5.1 服务启动

服务启动后读取本地数据文件，恢复玩家、设置、历史回合、奖池余额、统计偏移、审计日志和随机回合序号。如果数据文件不存在，服务器创建默认数据。

服务启动后，如果游戏没有暂停，并且当前没有正在进行的回合，服务器立即创建新回合。

服务器使用一个固定循环推动游戏状态。当前实现每 50 毫秒执行一次循环。后台存在“服务端循环间隔”参数，当前代码实际循环仍固定为 50 毫秒；生产版本如果要让该参数生效，需要让定时器读取该参数。

### 5.2 创建新回合

创建新回合时，服务器按顺序执行：

1. 生成本局内部随机种子。
2. 读取当前回合序号。
3. 回合序号加 1，供下一局使用。
4. 用本局随机种子和回合序号生成随机摘要。
5. 根据随机摘要、1.00x 即爆概率、平台边际和最大随机爆点计算本局随机爆点。
6. 把本局有效爆点初始化为随机爆点。
7. 记录回合创建时间。
8. 计算下注截止时间：回合创建时间 + 下注阶段时长。
9. 生成机器人下注计划。
10. 回合进入下注阶段。
11. 向所有在线客户端推送新回合事件。

新回合推送给玩家端的数据只包含公开状态，不包含任何爆点推算材料。

### 5.3 下注阶段

真实玩家下注时，服务器按顺序校验：

1. 当前回合必须存在。
2. 当前回合必须处于下注阶段。
3. 玩家必须存在。
4. 下注金额必须大于等于最小下注。
5. 下注金额必须小于等于最大下注。
6. 下注金额必须命中某个筹码档位。
7. 玩家余额必须足够。
8. 玩家本局不能已经下注。
9. 如果开启自动取现，自动取现倍率必须大于等于 1.01x，并且不超过最大随机爆点。

校验通过后，服务器按顺序执行：

1. 如果本次提交了自动取现倍率，把它保存为该玩家默认自动取现倍率。
2. 从玩家余额扣除下注金额。
3. 把下注金额加入奖池余额。
4. 创建真实玩家订单，状态为未取现。
5. 根据新的奖池余额和未取现真实下注重新计算有效爆点。
6. 写入审计日志。
7. 保存数据。
8. 向所有客户端推送下注增量事件。
9. 向该玩家推送余额更新。

奖池余额不足不是下注失败原因。奖池只通过有效爆点影响本局何时爆炸。

### 5.4 机器人下注阶段

每局创建时，服务器根据后台机器人参数生成本局机器人下注计划。机器人不会一次性出现在玩家列表，而是按照计划时间陆续下注。

服务器循环执行时，如果当前仍处于下注阶段，会检查是否有机器人到达下注时间。到达时间的机器人被创建为机器人订单，并通过下注增量事件推送给前端。

机器人下注不会扣除任何真实余额，不会增加奖池，不会进入平台盈亏，只影响本局玩家列表展示、总人数和机器人数量统计。

### 5.5 起飞

服务器当前时间到达下注截止时间后，回合从下注阶段进入飞行阶段。

起飞时，服务器按顺序执行：

1. 如果本局只有机器人下注，没有真实玩家下注，先检查是否触发纯机器人高飞逻辑。
2. 记录起飞时间。
3. 把当前倍率设为 1.00x。
4. 固定本局飞行倍率曲线参数。
5. 向客户端推送起飞事件。起飞事件包含回合编号、起飞时间和曲线参数，不包含爆点。

### 5.6 飞行循环

回合处于飞行阶段时，每次服务器循环按顺序执行：

1. 用服务器当前时间减去起飞时间，得到真实飞行时长。
2. 用真实飞行时长和本局倍率曲线计算当前服务器倍率。
3. 把当前服务器倍率向下截断到两位小数。
4. 处理所有已经达到目标倍率的自动取现。
5. 每处理一笔真实玩家自动取现后，奖池和剩余未取现真实下注都会变化，因此重新计算有效爆点。
6. 自动取现处理完成后，再重新计算有效爆点。
7. 如果当前服务器倍率大于等于有效爆点，服务器立即结算爆炸。
8. 如果没有爆炸，保存必要状态并等待下一次循环。

顺序不能颠倒。自动取现必须先于爆炸判定处理，这样才能保证自动取现目标低于有效爆点时一定成功。

### 5.7 自动取现

自动取现只由服务器执行。前端只在下注时提交目标倍率，之后即使玩家断网、页面切后台或前端没有刷新，只要服务器回合继续运行，自动取现仍按服务器倍率执行。

服务器处理自动取现时，逐笔检查未取现订单：

1. 订单必须仍处于未取现状态。
2. 订单必须设置了自动取现目标。
3. 当前服务器倍率必须大于等于自动取现目标。
4. 自动取现目标必须小于当前有效爆点。

满足条件后，服务器按自动取现目标倍率结算该订单，而不是按当前循环已经到达的更高倍率结算。这样可以避免服务器循环间隔造成自动取现多拿倍率。

### 5.8 手动取现

玩家手动取现时，前端只发送玩家身份，不发送倍率。

服务器收到手动取现请求后，按顺序执行：

1. 当前回合必须处于飞行阶段。
2. 玩家必须有本局未取现订单。
3. 先按当前奖池和未取现真实下注重新计算有效爆点。
4. 用请求到达服务器时的服务器时间计算当前服务器倍率。
5. 再次重新计算有效爆点，避免并发状态变化。
6. 如果当前服务器倍率大于等于有效爆点，先判定爆炸，玩家本次手动取现失败。
7. 如果当前服务器倍率小于有效爆点，按当前服务器倍率结算订单。
8. 给玩家余额增加返还金额。
9. 从奖池余额扣除返还金额。
10. 重新计算有效爆点。
11. 写入审计日志。
12. 保存数据。
13. 推送取现增量事件和玩家余额更新。

手动取现位置取决于请求到达服务器时的服务器倍率，不取决于前端画面显示的倍率。

### 5.9 爆炸与下一局

当当前服务器倍率大于等于有效爆点时，服务器结算爆炸。

爆炸时，服务器按顺序执行：

1. 所有仍未取现的订单变成失败。
2. 当前倍率设置为有效爆点。
3. 记录爆炸时间。
4. 设置下一局开始时间：爆炸时间 + 爆炸结果停留时长。
5. 统计真实玩家总下注。
6. 统计真实玩家总返还。
7. 计算平台盈亏。
8. 统计真实玩家人数、机器人人数和总人数。
9. 写入回合历史。
10. 向客户端推送爆炸事件。
11. 向每个相关玩家推送个人历史和余额更新。
12. 爆炸画面停留 3 秒。
13. 3 秒后服务器清理当前回合，创建下一局。

爆炸事件才会把最终爆点告诉玩家端。爆炸前不公开爆点。

## 6. 爆点生成公式

### 6.1 随机数来源

每局服务器内部生成一个随机种子，并使用递增回合序号参与计算。

| 公式名称   | 公式                        | 说明                                 |
| ------ | ------------------------- | ---------------------------------- |
| 随机摘要   | H = HMAC-SHA256(S, N)     | S 是本局内部随机种子，N 是递增回合序号，H 是十六进制随机摘要。 |
| 基础随机样本 | X = hexToInt(left(H, 13)) | 取随机摘要前 13 个十六进制字符，按十六进制转成整数。       |
| 随机分母   | D = 16^13                 | 13 个十六进制字符的最大空间。                   |
| 基础随机数  | R = X ÷ D                 | R 是大于 0 且小于 1 的随机小数。               |

基础随机数是大于 0 且小于 1 的小数。后续爆点计算都从这个基础随机数开始。

### 6.2 1.00x 即爆概率

后台配置“1.00x 即爆概率”，单位是万分比。

| 公式名称  | 公式            | 说明                              |
| ----- | ------------- | ------------------------------- |
| 即爆概率  | q = Q ÷ 10000 | Q 是后台配置的 1.00x 即爆概率，单位是万分比。     |
| 即爆判断  | R < q         | 如果基础随机数小于即爆概率，本局随机爆点直接等于 1.00x。 |
| 未即爆判断 | R ≥ q         | 如果基础随机数大于等于即爆概率，本局继续计算普通爆点。     |

如果基础随机数小于即爆概率，本局随机爆点直接等于 1.00x。

如果基础随机数大于等于即爆概率，本局没有命中 1.00x 即爆，继续计算普通爆点。

示例：

- 1.00x 即爆概率配置为 150。
- q = 150 ÷ 10000 = 0.015，也就是 1.5%。
- 如果基础随机数是 0.010，因为 0.010 小于 0.015，本局随机爆点是 1.00x。
- 如果基础随机数是 0.200，因为 0.200 大于 0.015，本局进入普通爆点计算。

这个逻辑的含义是：0 到 1 的随机区间中，最前面的 1.5% 专门留给 1.00x 即爆。

### 6.3 普通爆点

没有命中 1.00x 即爆时，需要把剩余随机区间重新映射到 0 到 1。

| 公式名称     | 公式                             | 说明                                           |
| -------- | ------------------------------ | -------------------------------------------- |
| 调整后随机数   | R_adjusted = (R - q) ÷ (1 - q) | R_adjusted 是去掉 1.00x 即爆区间后的标准随机数，范围仍是 0 到 1。 |
| 平台边际系数   | h = 1 - B ÷ 10000              | B 是后台配置的平台边际，单位是万分比。                         |
| 普通原始爆点   | C_raw = h ÷ (1 - R_adjusted)   | 随机数越接近 1，原始爆点越高。                             |
| 普通爆点     | C = floor(C_raw × 100) ÷ 100   | 普通爆点向下截断到两位小数。                               |
| 最小普通爆点保护 | C = max(C, 1.01)               | 普通爆点不能低于 1.01x。                              |
| 最大随机爆点保护 | C = min(C, C_max)              | C_max 是后台配置的最大随机爆点。                          |

如果普通爆点小于 1.01x，按 1.01x 处理。

如果普通爆点大于最大随机爆点，按最大随机爆点处理。

最终随机爆点规则：

| 公式名称        | 公式              | 说明               |
| ----------- | --------------- | ---------------- |
| 命中即爆时的随机爆点  | C_random = 1.00 | 基础随机数落入即爆区间。     |
| 未命中即爆时的随机爆点 | C_random = C    | C 是普通爆点公式计算出的结果。 |

随机爆点不一定是最终爆炸位置。最终爆炸位置还会被奖池承受能力限制。

## 7. 奖池控制有效爆点

奖池控制的目标是：如果剩余未取现真实玩家都在同一倍率取现，返还总额不能超过奖池余额。

| 公式名称       | 公式                                            | 说明                                          |
| ---------- | --------------------------------------------- | ------------------------------------------- |
| 剩余未取现真实下注额 | A_open = Σ A_i                                | 只统计当前回合所有未取现真实玩家下注金额，不统计机器人。                |
| 奖池可承受倍率    | C_pool = floor((P_pool ÷ A_open) × 100) ÷ 100 | P_pool 是当前奖池余额。结果向下截断到两位小数。                 |
| 有效爆点       | C_effective = min(C_random, C_pool)           | C_random 是随机爆点，C_effective 是服务器真正用于爆炸判断的爆点。 |
| 爆炸判断       | M_server ≥ C_effective                        | M_server 是服务器当前倍率。满足条件时火箭爆炸。                |

如果剩余未取现真实下注额等于 0，说明没有真实玩家风险，奖池不限制爆点。

奖池可承受倍率需要向下截断到两位小数。

当服务器当前倍率大于等于有效爆点时，火箭爆炸。

示例：

- 随机爆点是 25.00x。
- 奖池余额是 1000。
- 剩余未取现真实下注额是 100。
- C_pool = floor((1000 ÷ 100) × 100) ÷ 100 = 10.00x。
- C_effective = min(25.00, 10.00) = 10.00x。
- 火箭会在 10.00x 爆炸。

玩家成功取现后，奖池余额会减少，剩余未取现真实下注额也会减少。服务器必须重新计算奖池可承受倍率和有效爆点。

这个机制不能表现为“奖池不足，拒绝下注”或“奖池不足，拒绝取现”。对玩家来说，表现只能是火箭在服务器判定的有效爆点爆炸。

## 8. 飞行倍率曲线公式

倍率曲线只由服务器时间和本局曲线参数决定。前端可以用同样公式做动画，但结算只看服务器计算结果。

### 为什么分为前段和后段

飞行曲线分为前段和后段，是为了同时满足普通玩家体验和高倍率展示。

前段是 1.00x 到 20.00x。这个区间是绝大多数真实玩家下注、观察、手动取现和自动取现的主要区间，因此需要精细控制速度。前段使用幂函数公式，可以让火箭起步较慢，给玩家足够的观察和取现时间，同时在接近 20.00x 时逐渐加速。

后段是超过 20.00x 后的高倍率区间。这个区间通常真实玩家较少，主要用于高倍展示、机器人高飞和历史结果丰富度。如果继续使用前段同一条幂函数，高倍率可能增长过慢，100x 到 500x 会等待太久。因此后段使用指数增长，让高倍率能够持续上升，同时用后段增长时间常数单独控制速度。

20.00x 只是曲线切换点，不是玩法边界。玩家可以在 20.00x 前后正常取现，服务器仍然只按有效爆点判断是否爆炸。

拆成两段的好处：

- 前段可以单独调慢，照顾真实玩家操作体验。
- 后段可以单独调快，避免高倍局拖太久。
- 运营可以分别调整“多久到 20x”和“20x 之后涨多快”。
- 前段曲线指数 p 只影响 1.00x 到 20.00x，不影响 20.00x 之后。
- 后段增长时间常数 L 只影响 20.00x 之后，不影响前段手感。

### 8.1 参数定义

| 符号    | 中文名称     | 默认值      | 说明                             |
| ----- | -------- | --------:| ------------------------------ |
| t     | 飞行时长     | 按服务器时间计算 | t = 服务器当前时间 - 起飞时间，单位毫秒。       |
| T     | 前段总时长    | 35000 毫秒 | 后台配置的“前段到达 20.00x 的时长”。        |
| p     | 前段曲线指数   | 2.4      | 幂函数指数，用在 r^p 里，决定前段前慢后快的程度。    |
| w     | 前段线性权重   | 0.02     | 固定值，用于避免 1.00x 附近完全不动。         |
| M0    | 前段目标倍率   | 20.00x   | 前段结束时的目标倍率。                    |
| L     | 后段增长时间常数 | 12000 毫秒 | 20.00x 之后指数增长的时间常数。            |
| C_max | 展示和计算上限  | 按配置计算    | 取最大随机爆点、本局有效爆点、纯机器人高飞上下限中的最大值。 |

### 8.2 前段倍率公式

当前飞行时长小于或等于前段总时长时，使用前段公式。

前段曲线指数不是单独的一条公式，它是前段倍率公式里的参数 p。p 出现在 (t ÷ T)^p 这一项里，用来控制前段曲线前慢后快的程度。

完整前段公式：

| 公式名称   | 公式                                                          | 说明                                     |
| ------ | ----------------------------------------------------------- | -------------------------------------- |
| 前段原始倍率 | M_raw(t) = 1 + (M0 - 1) × (0.02 × t ÷ T + 0.98 × (t ÷ T)^p) | t 是飞行时长，T 是前段总时长，p 是前段曲线指数，M0 是前段目标倍率。 |
| 前段当前倍率 | M(t) = floor(M_raw(t) × 100) ÷ 100                          | 当前倍率向下截断到两位小数。                         |

默认参数代入后：

| 公式名称     | 公式                                                              | 说明                            |
| -------- | --------------------------------------------------------------- | ----------------------------- |
| 默认前段原始倍率 | M_raw(t) = 1 + 19 × (0.02 × t ÷ 35000 + 0.98 × (t ÷ 35000)^2.4) | 默认 T = 35000，p = 2.4，M0 = 20。 |
| 默认前段当前倍率 | M(t) = floor(M_raw(t) × 100) ÷ 100                              | 最终展示和结算倍率保留两位小数并向下截断。         |

为什么是 19：前段从 1.00x 增长到 20.00x，增长幅度是 20 - 1 = 19。

前段曲线指数 p 的含义：

- p = 1 时，(t ÷ T)^p 就是 t ÷ T，前段更接近线性增长。
- p > 1 时，前期的 (t ÷ T)^p 会小于 t ÷ T，所以前半段更慢，接近 20.00x 时变快。
- p 越大，前期越慢。
- p 越小，前期越快。

示例：

- 前段总时长是 35000 毫秒。
- 前段曲线指数 p 是 2.4。
- 飞行时长是 10000 毫秒。
- M_raw(t) = 1 + 19 × (0.02 × 10000 ÷ 35000 + 0.98 × (10000 ÷ 35000)^2.4)。

每局起飞时，服务器需要固定本局使用的前段曲线指数。后台在回合飞行中修改该参数时，不应改变已经起飞的当前回合，只影响后续新回合。

### 8.3 后段倍率公式

当前飞行时长大于前段总时长时，使用后段公式。

| 公式名称   | 公式                                 | 说明                   |
| ------ | ---------------------------------- | -------------------- |
| 超过前段时间 | u = t - T                          | u 是超过前段总时长后的飞行时间。    |
| 后段原始倍率 | M_raw(t) = M0 × e^(u ÷ L)          | M0 = 20，L 是后段增长时间常数。 |
| 后段当前倍率 | M(t) = floor(M_raw(t) × 100) ÷ 100 | 当前倍率向下截断到两位小数。       |

这里的 e 是自然常数，约等于 2.71828。

示例：

- 前段总时长是 35000 毫秒。
- 后段增长时间常数是 12000 毫秒。
- 飞行时长是 47000 毫秒。
- u = 47000 - 35000 = 12000 毫秒。
- u ÷ L = 12000 ÷ 12000 = 1。
- M_raw(t) = 20 × e^1 ≈ 54.36x。

### 8.4 完整分段曲线

| 公式名称 | 公式                                                                    | 说明                                    |
| ---- | --------------------------------------------------------------------- | ------------------------------------- |
| 前段曲线 | 0 ≤ t ≤ T：M_raw(t) = 1 + (M0 - 1) × (0.02 × t ÷ T + 0.98 × (t ÷ T)^p) | 这是 1.00x 到 20.00x 的完整前段公式。p 就是前段曲线指数。 |
| 后段曲线 | t > T：M_raw(t) = M0 × e^((t - T) ÷ L)                                 | 这是超过 20.00x 后的指数增长公式。                 |
| 最终倍率 | M(t) = floor(min(max(M_raw(t), 1), C_max) × 100) ÷ 100                | 先限制上下限，再向下截断到两位小数。                    |

### 8.5 倍率上限和异常保护

服务器先按前段或后段公式算出原始倍率，再执行保护：

1. 倍率不能低于 1.00x。
2. 倍率不能超过服务器允许展示和计算的上限。
3. 当前倍率向下截断到两位小数。
4. 如果公式结果不是有效数字，生产版本必须立刻刷新状态或使用上限保护，不能向玩家显示 Infinityx 或 NaNx。

服务器允许展示和计算的上限应取以下值中的最大值：

- 最大随机爆点。
- 本局实际有效爆点。
- 纯机器人高飞下限。
- 纯机器人高飞上限。

这样可以支持普通最大随机爆点为 100x，同时纯机器人高飞可以到 100x 到 500x。

## 9. 火箭视觉轨迹公式

火箭视觉轨迹只影响画面，不参与结算。

| 公式名称  | 公式                                      | 说明                                 |
| ----- | --------------------------------------- | ---------------------------------- |
| 视觉进度  | g = clamp(ln(M_display) ÷ ln(12), 0, 1) | M_display 是前端显示倍率，g 是 0 到 1 的视觉进度。 |
| 可用宽度  | W_use = W - 2P_x                        | W 是画布宽度，P_x 是左右边距。                 |
| 可用高度  | H_use = H - 2P_y                        | H 是画布高度，P_y 是上下边距。                 |
| 火箭横坐标 | x = P_x + g × W_use                     | 视觉进度越大，火箭越靠右。                      |
| 火箭纵坐标 | y = H - P_y - g^1.45 × H_use            | 视觉进度越大，火箭越靠上。                      |

轨迹线从视觉进度 0 画到当前视觉进度。每个采样点都用同样的横坐标和纵坐标公式。

这个公式会让火箭从左下向右上飞。倍率增长越高，视觉进度越接近 1，火箭越靠近右上角。

## 10. 1 秒显示延迟和网络延迟

生产设计中，前端显示比服务器真实飞行慢 1 秒。

| 公式名称      | 公式                                  | 说明                       |
| --------- | ----------------------------------- | ------------------------ |
| 服务器真实飞行时长 | t_server = T_server_now - T_launch  | 使用服务器时间，不使用用户本地系统时间。     |
| 前端显示飞行时长  | t_display = max(t_server - 1000, 0) | 前端显示固定比服务器真实飞行慢 1000 毫秒。 |
| 前端显示倍率    | M_display = M(t_display)            | 把前端显示飞行时长代入飞行倍率曲线。       |

起飞后的前 1000 毫秒，前端显示 Starting Soon。这个延迟只影响视觉，不影响服务器结算。

服务器时间同步规则：

1. 服务端响应返回服务器时间。
2. 实时同步消息携带服务器时间。
3. 前端收到服务器时间后，用浏览器的高精度运行时间推进服务器时间估算。
4. 前端不能依赖用户本地系统时间，因为用户本地时间可能不准。
5. 页面从后台回到前台时，前端必须重新请求状态和同步服务器时间。

取现影响：

- 自动取现由服务器执行，不受前端 1 秒显示延迟影响。
- 手动取现按请求到达服务器时的服务器倍率结算。
- 如果玩家网络延迟超过 1 秒，前端在下注前应弹出提示，说明画面可能滞后，建议使用自动取现。
- 即使前端画面还没显示到爆点，只要服务器当前倍率已经到达有效爆点，手动取现请求就会失败。

## 11. 机器人逻辑

### 11.1 机器人数量

每局机器人数量在“每局机器人最少数量”和“每局机器人最多数量”之间随机取整数。

如果下注窗口和最小下注间隔无法容纳配置数量，服务器按可容纳数量安排机器人，避免所有机器人挤在最后一刻下注。

### 11.2 机器人下注时间

第一个机器人最早在回合创建后 350 毫秒下注。

| 公式名称     | 公式                                                            | 说明                       |
| -------- | ------------------------------------------------------------- | ------------------------ |
| 最早下注时间   | T_first_bot = T_round_create + 350                            | 第一个机器人最早在回合创建后 350 毫秒下注。 |
| 最晚下注时间   | T_last_bot = T_bet_end - 1100                                 | 机器人最晚在下注截止前 1100 毫秒下注。   |
| 可安排机器人上限 | N_schedulable = floor((T_last_bot - T_first_bot) ÷ I_min) + 1 | I_min 是机器人下注最小间隔。        |

机器人之间的下注间隔在“机器人下注最小间隔”和“机器人下注最大间隔”之间随机。

服务器会保证剩余机器人在剩余时间里仍能排下。如果剩余时间不足，会缩短本次随机间隔到可排下的范围。

### 11.3 机器人下注金额

机器人下注金额必须来自筹码档位。

服务器先筛选在“机器人最小下注”和“机器人最大下注”范围内的筹码档位，再随机选择一个档位。

如果没有筹码档位落在机器人下注范围内，服务器从全部筹码档位中随机选择。

### 11.4 机器人自动取现

机器人都会生成一个自动取现目标。

机器人自动取现目标分布：

- 58% 的机器人目标在 1.15x 到 2.50x。
- 30% 的机器人目标在 2.50x 到 6.00x。
- 12% 的机器人目标在 6.00x 到 20.00x。

机器人目标倍率最终限制在 1.01x 到最大随机爆点之间，并保留两位小数。

### 11.5 机器人结算口径

机器人订单可以显示为未取现、已取现或失败。

机器人订单可以出现在玩家列表和回合人数统计中。

机器人金额不能进入：

- 真实总下注。
- 真实总返还。
- 平台盈亏。
- 奖池余额。
- 玩家余额。

## 12. 纯机器人高飞逻辑

纯机器人高飞只用于没有真实玩家参与的回合，避免无人局频繁停在普通倍率。

触发条件必须全部满足：

1. 当前回合已有下注。
2. 所有下注都是机器人下注。
3. 没有任何真实玩家下注。
4. 机器人功能开启。
5. 本局还没有检查过纯机器人高飞。

| 公式名称       | 公式                                        | 说明                                |
| ---------- | ----------------------------------------- | --------------------------------- |
| 纯机器人高飞触发概率 | q_bot_high = Q_bot_high ÷ 10000           | Q_bot_high 是后台配置的纯机器人高飞概率，单位是万分比。 |
| 高飞爆点       | C_bot_high = random(C_bot_min, C_bot_max) | 在纯机器人高飞下限和上限之间随机取两位小数。            |

如果随机命中，服务器把本局随机爆点改为一个高倍率。

默认高飞范围是 100.00x 到 500.00x。

只要本局有真实玩家下注，纯机器人高飞逻辑绝对不能生效。

- 当前在线玩家数。
- 历史回合数。
- 真实总下注。
- 真实总返还。
- 平台盈亏。
- 当前真实下注。

- 如果当前回合存在未取现真实玩家，立即重新计算有效爆点。

玩家管理：

- 可搜索玩家。
- 可查看玩家余额、创建时间、更新时间和最近在线时间。
- 可调整玩家余额。
- 调整金额可以为正数或负数。
- 调整后余额不能小于 0。
- 玩家余额调整只影响该玩家余额，不直接改变奖池和平台盈亏。
- 调整必须写入审计日志。

强制爆炸：

- 当前没有可控制回合时不能操作。
- 如果当前回合在下注阶段，强制爆炸前先切换到飞行阶段。
- 强制爆点不能低于当前服务器倍率。
- 强制爆点不能超过最大随机爆点和奖池可承受倍率。
- 强制爆炸的回合必须在历史中标记。

维护操作：

- 清理平台盈亏统计：只清理展示统计，不删除玩家、不删除回合、不改变余额、不改变奖池。
- 清理回合记录：删除历史回合，并重置统计偏移，不删除玩家和当前回合。

## 15. 自动维护和熔断机制

自动维护和熔断机制用于处理异常状态。它不是正常奖池控制逻辑，也不能替代有效爆点机制。

正常情况下，奖池风险通过有效爆点控制，不能向玩家展示“奖池不足”，也不能因此拒绝合法下注或合法取现。只有当系统状态已经不可信，例如奖池为负、参数无法修复、倍率计算异常或服务器结算流程报错时，才进入自动维护。

### 15.1 熔断触发条件

出现以下任一情况，服务器必须触发熔断：

1. 奖池余额小于 0。
2. 当前回合有效爆点不是有效数字。
3. 当前倍率不是有效数字，或者出现 Infinity、NaN。
4. 当前倍率小于 1.00x。
5. 下注上限小于下注下限。
6. 筹码档位为空，或所有筹码都不在下注上下限范围内。
7. 1.00x 即爆概率小于 0 或大于 10000。
8. 平台边际小于 0 或大于 2500。
9. 最大随机爆点小于 2.00x。
10. 前段总时长、前段曲线指数、后段增长时间常数不在允许范围内。
11. 机器人最少数量大于机器人最多数量。
12. 机器人下注最小间隔大于机器人下注最大间隔。
13. 纯机器人高飞下限大于纯机器人高飞上限。
14. 数据文件读取失败且无法恢复。
15. 数据写入失败。
16. 回合结算时发现真实玩家返还会导致奖池变成负数。
17. 服务器主循环发生未捕获错误。
18. 服务器时间异常回退，导致飞行时长变成负数。
19. 当前回合缺失关键字段，例如回合编号、阶段、起飞时间、下注列表或爆点。

### 15.2 自动维护状态

触发熔断后，服务器进入自动维护状态。

自动维护状态下必须执行：

1. 停止创建新回合。
2. 停止接受新下注。
3. 停止机器人继续下注。
4. 保留当前回合、玩家、奖池、下注、历史和审计现场。
5. 写入审计日志，记录触发原因、当前回合、奖池余额、当前倍率、有效爆点和服务器时间。
6. 玩家端显示系统维护中。
7. 后台显示维护原因和恢复建议。

自动维护状态不能静默失败。玩家端必须知道游戏暂时不可继续，但不需要知道奖池和爆点内部细节。

### 15.3 不同阶段的处理

如果熔断发生在没有当前回合时：

- 服务器停止创建新回合。
- 等待后台修复参数或数据。

如果熔断发生在下注阶段：

- 服务器立即关闭下注。
- 未起飞的真实玩家下注应优先原路退回玩家余额。
- 已退回的下注必须从奖池中扣回。
- 本局标记为维护取消，不进入正常历史爆点。
- 如果退款过程中再次失败，保持维护状态并等待人工处理。

如果熔断发生在飞行阶段：

- 如果倍率计算、有效爆点和奖池都仍然可信，服务器可以按当前有效爆点完成本局结算，然后进入维护状态，不再开新局。
- 如果倍率、爆点或奖池已经不可信，服务器必须冻结当前回合，不再继续飞行，不再自动结算，等待人工审计处理。
- 飞行阶段不能因为熔断随意修改玩家已成功取现的订单。

如果熔断发生在爆炸停留阶段：

- 已完成的结算结果保持不变。
- 服务器停止进入下一局。
- 后台修复后再恢复开局。

### 15.4 参数自动修复规则

可安全修复的参数，服务器可以自动修复并写入审计日志：

| 异常             | 自动修复                   |
| -------------- | ---------------------- |
| 下注时长超出范围       | 截断到允许范围内。              |
| 1.00x 即爆概率超出范围 | 截断到 0 到 10000。         |
| 平台边际超出范围       | 截断到 0 到 2500。          |
| 前段总时长超出范围      | 截断到 10000 到 120000 毫秒。 |
| 前段曲线指数超出范围     | 截断到 1 到 5。             |
| 后段增长时间常数超出范围   | 截断到 3000 到 60000 毫秒。   |
| 机器人数量为负数       | 修复为 0。                 |
| 历史记录过长         | 保留最新记录，裁剪旧记录。          |

不能安全修复的参数，必须触发维护：

- 最小下注大于最大下注。
- 筹码档位为空。
- 奖池为负。
- 当前回合爆点不是有效数字。
- 当前回合阶段无法识别。
- 数据无法写入。

### 15.5 奖池为负的处理

奖池为负是严重异常，不属于正常玩法。

正常奖池不足时，服务器应通过有效爆点提前爆炸，不应该让奖池变成负数。如果奖池已经小于 0，说明系统存在数据损坏、结算重复、人工误操作或并发错误。

奖池为负时：

1. 立即进入自动维护。
2. 停止新下注和新回合。
3. 冻结当前奖池余额和当前回合。
4. 写入审计日志。
5. 后台必须先把奖池修复到大于等于 0。
6. 修复后才能恢复游戏。

### 15.6 恢复规则

从自动维护恢复时，必须满足：

1. 奖池余额大于等于 0。
2. 所有参数通过范围校验。
3. 当前没有不可信的飞行中回合。
4. 数据文件可读可写。
5. 最近一次审计记录中已写入恢复操作。

恢复后，服务器从新回合开始，不应继续使用已经取消或冻结的异常回合。

## 16. 玩家端公开数据

玩家端可以接收：

- 当前回合编号。
- 当前回合阶段。
- 当前倍率快照。
- 下注截止时间。
- 起飞时间。
- 爆炸时间。
- 下一局开始时间。
- 本局是否强制爆炸。
- 本局是否被奖池限制。
- 奖池限制倍率。
- 倍率曲线公开参数。
- 玩家列表。
- 爆炸后的最终爆点。
- 历史爆点。
- 当前玩家余额。
- 当前玩家个人下注历史。

玩家端不能接收：

- 服务端随机种子。
- 种子哈希。
- 随机摘要。
- 未爆炸前的爆点。
- 可复算爆点的内部材料。

## 17. 回合记录和统计

回合结束后保存：

- 回合编号。
- 回合序号。
- 随机爆点。
- 有效爆点。
- 是否强制爆炸。
- 是否纯机器人高飞。
- 是否被奖池限制。
- 奖池限制倍率。
- 创建时间。
- 起飞时间。
- 爆炸时间。
- 真实玩家总下注。
- 真实玩家总返还。
- 平台盈亏。
- 总人数。
- 真实玩家人数。
- 机器人人数。
- 真实玩家订单明细。

平台盈亏计算：

| 公式名称  | 公式                         | 说明                    |
| ----- | -------------------------- | --------------------- |
| 真实总下注 | B_real = Σ A_i             | 只统计真实玩家下注金额，不统计机器人。   |
| 真实总返还 | P_real = Σ P_i             | 只统计真实玩家成功取现返还，不统计机器人。 |
| 平台盈亏  | H_profit = B_real - P_real | 正数表示平台盈利，负数表示平台亏损。    |

机器人金额不进入平台盈亏。

## 18. 生产验收规则

1. 玩家只能在下注阶段下注。
2. 玩家每局最多下注一次。
3. 下注金额必须命中筹码档位。
4. 合法下注不能因为奖池余额不足被拒绝。
5. 真实玩家下注成功后，玩家余额减少，奖池增加。
6. 手动取现按请求到达服务器时的服务器倍率结算。
7. 手动取现请求不能携带倍率。
8. 奖池不足不能作为取现流程直接拒绝理由。
9. 奖池风险必须通过动态有效爆点控制。
10. 自动取现必须由服务器执行。
11. 自动取现目标低于有效爆点时，必须在爆点前结算。
12. 当前服务器倍率达到有效爆点时，所有未取现订单必须失败。
13. 爆炸后必须停留 3 秒，再清理数据并开始下一局倒计时。
14. 玩家端爆炸前不能收到爆点。
15. 玩家端不能收到种子哈希、服务端种子或随机摘要。
16. 机器人金额不能进入真实奖池、真实总下注、真实总返还和平台盈亏。
17. 机器人下注必须按后台间隔陆续出现。
18. 有真实玩家下注时，纯机器人高飞逻辑不能生效。
19. 飞行中不能持续推送倍率。
20. 前端显示倍率不能作为结算依据。
21. 前端不能依赖用户本地系统时间作为结算依据。
22. 页面切后台再回来后，前端必须重新同步服务器状态。
23. 延迟超过 1 秒时，下注前必须提示玩家手动取现可能受影响，并建议使用自动取现。
24. 公式异常时不能显示 Infinityx 或 NaNx。
25. 后台关键操作必须写入审计日志。
26. 奖池余额小于 0 时，游戏必须自动进入维护状态。
27. 参数无法安全修复时，游戏必须自动进入维护状态。
28. 数据读取、写入或服务器主循环异常时，游戏必须自动进入维护状态。
29. 自动维护状态下不能创建新回合，不能接受新下注。
30. 自动维护恢复前，必须确认奖池、参数、当前回合和数据读写状态全部可信。
